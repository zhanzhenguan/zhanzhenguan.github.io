一、版本基线

结论：Spring Boot 3.5.16 + Spring Security 6.5.11 + JJWT 0.13.0 + JDK 17。

组件 版本 说明
JDK 17 Spring Boot 3.x 最低要求
Spring Boot 3.5.16 依赖统一交给 BOM
Spring Security 6.5.11 随 Boot 3.5.16 引入，无需手动指定版本
JJWT 0.13.0 api / impl / jackson 三个构件，版本必须一致

两个版本原则：

  1. Spring Security 版本交给 Spring Boot 管。Boot 3.5.16 依赖清单管理的就是 Security 6.5.11，自己在 pom 里写版本号反而容易混搭出不兼容组合；
  2. JJWT 三个构件用同一个版本属性。jjwt-api 是编译期接口，jjwt-impl、jjwt-jackson 是运行时实现，版本不一致是 ClassNotFoundException 的头号来源。

二、JWT 基础

JWT（JSON Web Token） 是在各方之间以 JSON 对象安全传递声明的开放标准。认证流程：用户登录成功后服务端签发 Token → 客户端保存 Token → 后续请求带上 Token → 服务端验证签名和有效期后识别用户。全程服务端不存会话，天然适合前后端分离和 RESTful API。

一个签名 JWT 三段以句点分隔：

部分 作用 常见内容
Header（头部） 描述令牌类型及签名算法 alg=HS256、typ=JWT
Payload（载荷） 存放声明（Claims） sub、iss、iat、exp、业务用户标识
Signature（签名） 验证内容是否被篡改 用密钥对前两段签名

必须刻在脑子里的常识：Base64URL 编码不是加密。 任何拿到 JWT 的人都能解码出 Header 和 Payload，所以 Claims 里永远不要放密码、身份证号、银行卡号、密钥。签名的作用是防篡改，不是隐藏内容。

常用标准声明：

声明 含义
iss Issuer，签发者
sub Subject，主题，通常放用户唯一标识
aud Audience，接收方
iat Issued At，签发时间
exp Expiration Time，过期时间
nbf Not Before，生效时间
jti JWT ID，令牌唯一标识，可用于撤销/防重放设计

完整认证链路：

  1. 客户端提交用户名和密码；
  2. 服务端通过 AuthenticationManager 委托认证组件校验账号密码；
  3. 认证成功后签发 JWT 返回给客户端；
  4. 客户端保存 Token，后续请求在 Authorization 头携带 Bearer Token；
  5. JWT 过滤器提取 Token，校验签名、有效期及必要声明；
  6. 校验通过后把用户身份写入 SecurityContextHolder，后续授权规则据此判断放行与否。

注意 JWT 与 Spring Security 的分工：JWT 只负责令牌格式与签名；认证上下文、过滤器链、授权规则和安全异常处理都是 Spring Security 的事。两者是配合关系，不是替代关系。

四、配置 JWT 参数与密钥

app:

    # 密钥支持环境变量覆盖：开发用默认值，生产用 JWT_SECRET_BASE64 注入
    secret-base64: ${JWT_SECRET_BASE64:change-me-base64-at-least-32-bytes}

    # Access Token 有效期，毫秒；15 分钟是推荐量级
    access-token-expiration-ms: 900000

三个配置项：密钥支持环境变量覆盖；有效期 15 分钟是 Access Token 推荐量级；issuer 是签发者标识，签发和校验两侧必须一致，代码里强校验。

HS256 要求密钥解码后至少 32 字节（256 bit），不足会在创建密钥时直接抛 WeakKeyException——这是 JJWT 的安全保护，属于预期行为，不要绕过。生产环境密钥不要提交 Git，走环境变量、密钥管理服务或部署平台 Secret。

五、JwtService：Token 生成与校验

JwtService 是整合核心：生成 Token、解析 Claims、校验有效性。密钥经 Base64 解码后创建 HMAC 密钥。

@Slf4j
@Service
public class JwtService {

    private final SecretKey key;
    private final String issuer;
    private final long expirationMs;

    public JwtService(@Value("${app.jwt.secret-base64}") String secretBase64,
                      @Value("${app.jwt.issuer}") String issuer,
                      @Value("${app.jwt.access-token-expiration-ms}") long expirationMs) {
        byte[] bytes = Base64.getDecoder().decode(secretBase64);
        if (bytes.length < 32) {
            throw new IllegalStateException("JWT 密钥解码后不足 32 字节");
        }
        this.key = Keys.hmacShaKeyFor(bytes);
        this.issuer = issuer;
        this.expirationMs = expirationMs;
    }

    public String generateToken(String username, Collection<String> roles) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + expirationMs);
        return Jwts.builder()
                .subject(username)
                .issuer(issuer)
                .issuedAt(now)
                .expiration(expiry)
                .claim("roles", roles)
                .signWith(key, Jwts.SIG.HS256)
                .compact();
    }

    public String extractUsername(String token) {
        return parse(token).getSubject();
    }

    public boolean isValid(String token) {
        try {
            parse(token);
            return true;
        } catch (Exception e) {
            log.warn("JWT 校验失败: {}", e.getMessage());
            return false;
        }
    }

    public long getExpiresInSeconds() {
        return expirationMs / 1000;
    }

    private Claims parse(String token) {
        return Jwts.parser()
                .verifyWith(key)
                .requireIssuer(issuer)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }
}

设计说明：

  • parseSignedClaims 内部验证签名并检查 exp、nbf 等标准时间声明，requireIssuer 额外校验签发者；解析失败即 Token 不可信，异常在 isValid 兜住返回 false；
  • 构造器检查密钥长度，配错密钥应用启动就失败，比带着弱密钥上线安全；
  • getExpiresInSeconds 从配置实时计算有效期，避免把 expiresIn 硬编码成 900，配置一改就和实际有效期对不上。

6.2 JWT 认证过滤器

过滤器继承 OncePerRequestFilter 保证一次请求只执行一次，从 Authorization 头提取 Bearer Token，验证成功后把 Authentication 放进 SecurityContextHolder。

@Slf4j
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    // 注意：本类不加 @Component，由 SecurityConfig 的 @Bean 方法装配
    public JwtAuthenticationFilter(JwtService jwtService, UserDetailsService userDetailsService) {
        this.jwtService = jwtService;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (jwtService.isValid(token)
                    && SecurityContextHolder.getContext().getAuthentication() == null) {
                String username = jwtService.extractUsername(token);
                UserDetails user = userDetailsService.loadUserByUsername(username);
                UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
                authentication.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }
        }
        chain.doFilter(request, response);
    }
}

两个容易写错的点：

  • 过滤器职责边界：没有 Token 时不要直接返回 401，只放行请求即可。登录、健康检查等公开接口本来就允许匿名访问，是否拦截是授权规则的事；过滤器越权拦截会把公开接口一起打死；
  • 循环依赖坑：这个类没有加 @Component。若按老教程写法给过滤器加 @Component 自动扫描、SecurityConfig 再构造注入过滤器，启动直接失败——闭环是：过滤器构造需要 UserDetailsService，而 UserDetailsService Bean 定义在 SecurityConfig 里，SecurityConfig 又要注入过滤器本身。Spring Boot 2.6 起默认禁止循环引用。解法就是上面写法：过滤器不加 @Component，由 SecurityConfig 的 @Bean 方法装配，依赖方向变单向，环就断了。

七、SecurityConfig：无状态安全链

Spring Security 6 的标准姿势：告别 WebSecurityConfigurerAdapter，全部通过 Bean 声明。

@Configuration
@EnableMethodSecurity
public class SecurityConfig {

    private final JwtService jwtService;

    public SecurityConfig(JwtService jwtService) {
        this.jwtService = jwtService;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http,
                                            AuthenticationConfiguration authConfig,
                                            PasswordEncoder passwordEncoder) throws Exception {
        UserDetailsService userDetailsService = userDetailsService(passwordEncoder);

        http.csrf(csrf -> csrf.disable())
            .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .formLogin(form -> form.disable())
            .httpBasic(basic -> basic.disable())
            .authorizeHttpRequests(auth -> auth
                    .requestMatchers("/auth/login", "/error").permitAll()
                    .requestMatchers("/api/admin/**").hasRole("ADMIN")
                    .anyRequest().authenticated())
            .exceptionHandling(e -> e
                    .authenticationEntryPoint(restEntryPoint())
                    .accessDeniedHandler(restAccessDeniedHandler()))
            .addFilterBefore(
                    new JwtAuthenticationFilter(jwtService, userDetailsService),
                    UsernamePasswordAuthenticationFilter.class);

        return http.build();
    }

    @Bean
    public UserDetailsService userDetailsService(PasswordEncoder encoder) {
        var admin = User.withUsername("admin")
                .password(encoder.encode("123456")).roles("ADMIN").build();
        var user = User.withUsername("user")
                .password(encoder.encode("123456")).roles("USER").build();
        return new InMemoryUserDetailsManager(admin, user);
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public RestAuthenticationEntryPoint restEntryPoint() {
        return new RestAuthenticationEntryPoint();
    }

    @Bean
    public RestAccessDeniedHandler restAccessDeniedHandler() {
        return new RestAccessDeniedHandler();
    }
}

逐块拆解：

  • csrf().disable()：CSRF 防的是 Cookie 被浏览器自动携带的攻击面。JWT 放在 Authorization 头里、完全无状态，这个攻击面不存在，所以关闭；若 Token 改放 Cookie，必须重新评估 CSRF，不能无脑关；
  • STATELESS：告诉 Spring Security 别创建别使用 HttpSession，每次请求身份完全来自 Token；
  • formLogin / httpBasic 显式关闭：不关的话部分场景会冒出默认登录页，REST 客户端收到 HTML 响应；
  • 授权规则从上到下匹配：permitAll 放行登录和 /error（/error 不放行会导致异常响应本身被拦截，出现二次 401）；/api/admin/** 要 ADMIN 角色；最后 anyRequest().authenticated() 兜底；
  • addFilterBefore：把 JWT 过滤器插在 UsernamePasswordAuthenticationFilter 之前，请求先走 Token 认证；
  • 内存用户：演示用 admin/123456（ADMIN）和 user/123456（USER），密码经 BCrypt 哈希；生产换成数据库 UserDetailsService，其余代码一行不用改。

角色判断注意：hasRole("ADMIN") 自动加 ROLE_ 前缀，检查 UserDetails 中 GrantedAuthority 实际值应为 ROLE_ADMIN。

八、401/403 统一 JSON 响应

Spring Security 默认 401 是空响应体、403 没有 JSON 结构，前后端联调别扭。两个小组件统一处理：

  • EntryPoint 处理「没登录」（401）：Token 缺失、过期、篡改都走这里；
  • AccessDeniedHandler 处理「登录了但没权限」（403）：Token 有效但角色不够走这里。
public class RestAuthenticationEntryPoint implements AuthenticationEntryPoint {
    @Override
    public void commence(HttpServletRequest request, HttpServletResponse response,
                         AuthenticationException authException) throws IOException {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"code\":401,\"message\":\"未认证或认证已失效，请先登录\"}");
    }
}
public class RestAccessDeniedHandler implements AccessDeniedHandler {
    @Override
    public void handle(HttpServletRequest request, HttpServletResponse response,
                       AccessDeniedException exception) throws IOException {
        response.setStatus(HttpServletResponse.SC_FORBIDDEN);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"code\":403,\"message\":\"权限不足，拒绝访问\"}");
    }
}

九、Controller 层

9.1 登录接口

认证细节交给 AuthenticationManager，不自己查库比对密码：它内部走 UserDetailsService 加载用户、PasswordEncoder 校验哈希，账号禁用锁定等 AuthenticationException 一并抛出，控制器只管捕获转 401。

@RestController
@RequiredArgsConstructor
public class AuthController {

    private final AuthenticationManager authenticationManager;
    private final JwtService jwtService;

    @PostMapping("/auth/login")
    public LoginResponse login(@Valid @RequestBody LoginRequest request) {
        try {
            Authentication authentication = authenticationManager.authenticate(
                    new UsernamePasswordAuthenticationToken(request.username(), request.password()));
            String username = authentication.getName();
            List<String> roles = authentication.getAuthorities().stream()
                    .map(GrantedAuthority::getAuthority).toList();
            String token = jwtService.generateToken(username, roles);
            return new LoginResponse("Bearer", token, jwtService.getExpiresInSeconds());
        } catch (AuthenticationException e) {
            throw new BadCredentialsException("用户名或密码错误", e);
        }
    }
}

十一、常见问题排查

问题 原因与处理
启动报循环依赖（filter ↔ securityConfig） 过滤器加 @Component 且被 SecurityConfig 构造注入；改为 @Bean 方法装配

401 但 Token 看起来正确 检查 Bearer 前缀、密钥是否一致、issuer 是否一致、是否过期、系统时间是否准确

访问接口返回 HTML 登录页 formLogin / httpBasic 未显式关闭，或用回了默认配置
角色判断失败 hasRole 自动加 ROLE_ 前缀，检查 GrantedAuthority 实际值
跨域请求失败 配置 CorsConfigurationSource，放行前端 Origin、Authorization、Content-Type 等头
注销后旧 Token 仍可访问 JWT 默认无法即时撤销；需 Redis 黑名单（jti + 剩余 TTL）或 tokenVersion 方案

十二、Token 过期、刷新与注销

Access Token 过期：建议 5～15 分钟短有效期，压缩泄露后的可利用窗口。过期后解析失败，客户端重新认证或用 Refresh Token 换新的。

Refresh Token 设计（生产方案要点）：

  1. 登录成功同时签发短期 Access Token 和较长期 Refresh Token；
  2. Refresh Token 用高熵随机值，服务端只存哈希及用户、过期时间、设备信息、状态；
  3. 刷新接口校验存在、未过期、未撤销，并做轮换：旧的失效、签发新的；
  4. 检测到旧 Refresh Token 被重复使用时，撤销整个令牌族；
  5. 登出时撤销服务端保存的 Refresh Token。

注销与黑名单：纯无状态 JWT 签发后服务端无法直接删除。要「立即踢下线」就用服务端状态：Redis 黑名单（jti 写入，TTL 设为剩余有效期）、用户 tokenVersion（改密码/强制下线时递增）、或 Refresh Token 会话表按设备撤销。这些方案引入服务端查询，严格说不再完全无状态，但能满足即时撤销。

十三、小结

  • 版本上 Security 交 BOM 管理，JJWT 三构件同版本；JWT 只负责令牌格式与签名，认证上下文、过滤器链、授权规则归 Spring Security；
  • JwtService 经 Base64 解码建 HMAC 密钥，签发时带 iss/sub/iat/exp，解析时验签 + 校验签发者与时间声明；
  • 认证过滤器不加 @Component，由 SecurityConfig 的 @Bean 装配以断开循环依赖；无 Token 只放行，不越权返回 401；
  • 安全链用 STATELESS、关 CSRF 与默认表单登录，EntryPoint 处理 401、AccessDeniedHandler 处理 403；
  • 生产闭环要补 Refresh Token 轮换、Redis 黑名单或 tokenVersion 实现即时撤销。
