一、基本概念与定位

1.1 它解决什么问题

早期 Java 开发（Spring + 传统 XML）配置繁多、第三方技术集成成本高、部署流程重。Spring Boot 的核心理念是**“习惯优于配置”**：对常见场景内置一套习惯性默认配置，开发者无须手动堆砌大量 XML 与 Bean 装配，就能快速跑起一个独立运行、准生产级别的 Spring 应用。

1.2 优点与局限

优点

  • 纯 Java 配置方式，注解驱动，上手简单；
  • 配合各类 Starter 实现自动化配置，依赖与默认约定成套提供；
  • 打成可执行 Jar 包后，java -jar 即可部署运行。

局限

  • 封装度较高，初期不容易看清底层装配过程；
  • 从传统 XML 配置迁移到 Java/注解配置，思维转变需要时间；
  • 部分 JavaConfig、自动配置相关问题资料较少，踩坑要靠读源码。

1.3 主要特性

  • 引导页面几秒即可生成一个项目骨架；
  • 可对外输出 REST API、WebSocket、Web、流式、定时任务等多种服务；
  • 内置简洁的安全策略集成；
  • 同时支持关系型与非关系型数据库；
  • 内嵌 Tomcat、Jetty、Undertow 等 Servlet 容器；
  • 提供开发工具包，支持热启动；
  • 自动管理依赖版本，自带应用监控；
  • 支持主流 IDE（IntelliJ IDEA、NetBeans 等）。

二、核心功能

  1. 独立运行：以 Jar 包形式独立运行，java -jar xx.jar 启动，不依赖外部容器部署。
  2. 内嵌 Servlet 容器：可选内嵌 Tomcat、Jetty、Undertow，无须打成 War 包部署到外部容器。
  3. Starter 简化 Maven 配置：提供一系列 starter pom 聚合常用依赖，引入后自动加载配套组件。
  4. 自动配置 Spring：根据类路径下的 Jar 包与类，自动为其装配 Bean；默认不覆盖的场景可再自定义自动配置。
  5. 准生产监控：基于 HTTP、SSH、Telnet 对运行时项目进行监控。
  6. 无代码生成、无 XML 配置：自动配置不是靠代码生成，而是通过条件注解（Spring 4.x 起的特性）实现，Java 配置 + 注解即可完成 Spring 装配。

三、手工搭建一个最小工程

3.1 Maven 父级依赖

引入 spring-boot-starter-parent 作为父依赖后，项目即成为 Spring Boot 工程；它提供 Maven 默认依赖版本管理，常用依赖可以省略 version 标签。

<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>2.7.x</version>
</parent>

3.2 Web 启动器 starter-web

spring-boot-starter-web 是 Web 开发核心依赖，一个依赖把构建 Web 应用所需组件聚合在一起：

  • Web 框架：Spring MVC，提供 @Controller、@RequestMapping 等注解；
  • 内嵌服务器：默认 Tomcat，可切换 Jetty 或 Undertow；
  • JSON 处理：Jackson，自动完成对象与 JSON 的序列化/反序列化；
  • 其他组件：自动配置、Actuator 监控相关、Validation 参数校验等。

它还做了默认的 Web 自动配置：装配 DispatcherServlet 处理 HTTP 请求、支持内容协商（JSON/XML 等）、配置静态资源访问、提供默认错误页面与异常处理。

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

引入前需要手动配置 Tomcat、Spring MVC、JSON 转换器；引入后零配置即可运行 Web 应用，版本兼容由启动器统一管理。

3.3 打包插件

spring-boot-maven-plugin 在打包时引入依赖，mvn package 会把工程打成可直接运行的 Jar，默认执行目标是 repackage：

<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>

3.4 入口类

Spring Boot 通常有一个命名 *Application 的入口类，main 方法是标准 Java 应用入口，通过 SpringApplication.run(...) 启动应用：

@SpringBootApplication
public class SpringbootApplication {
    public static void main(String[] args) {
        SpringApplication.run(SpringbootApplication.class, args);
    }
}

启动后默认访问 http://localhost:8080/；修改入口类中的方法内容需要重启服务才能生效。

四、核心注解与配置文件

4.1 入口类与 @SpringBootApplication

@SpringBootApplication 是一个组合注解，主要由 @Configuration、@EnableAutoConfiguration、@ComponentScan 组合而成；拆开来也可以在入口类上分别使用这三个注解。

  • @EnableAutoConfiguration：让 Spring Boot 根据类路径中的 Jar 依赖进行自动配置；
  • @ComponentScan：默认扫描入口类所在包及其子包下的 Bean（JPA 项目还会扫描标注 @Entity 的实体类）；
  • 建议入口类放在 groupId 与 artifactId 组合的基础包名下，保证扫描范围覆盖到业务代码。

关闭特定自动配置：通过 exclude 参数排除不需要的自动配置类：

@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
public class SpringbootApplication { ... }

4.2 全局配置文件

Spring Boot 使用全局配置文件 application.properties 或 application.yml，放在 src/main/resources 或类路径的 /config 目录下，用于覆盖默认配置值。YAML 是以数据为中心的配置语言，具有面向对象的特征。

YAML 基本语法

  • 大小写敏感；
  • 用缩进表示层级关系；
  • 缩进不能用 Tab，只能用空格；
  • 空格数量不重要，相同层级左对齐即可；
  • # 表示注释。

常用配置项示例：

spring:
  application:
    name: payment-demo   # 应用名称，微服务注册、监控、日志追踪中使用
server:
  port: 8090              # 服务器端口号
  http2:
    enabled: false        # 是否启用 HTTP/2，默认关闭
spring:
  profiles:
    active: dev           # 指定生效的 Profile 名称
spring:
  servlet:
    multipart:
      location: /tmp/upload   # 文件上传临时存储位置

几个易混配置的说明：

  • server.http2.enabled：控制内嵌服务器是否启用 HTTP/2。HTTP/2 通过多路复用、头部压缩、服务器推送等提升性能；启用需要客户端也支持，且通常要配合 HTTPS 满足浏览器安全要求。
  • spring.mvc.dispatch-options-request：控制是否把 HTTP OPTIONS 请求分发给 Controller 处理。为 true 时由控制器方法处理（无匹配则返回 405）；为 false 时由框架根据现有 @RequestMapping 自动生成 Allow 响应头并返回 200，不触发控制器。若启用了 CORS 跨域，OPTIONS 预检请求优先由 CORS 机制处理，该配置不再生效。

4.3 bootstrap.yml 与 application.yml 的区别

  • application 用于 Spring Boot 项目自身的自动化配置；
  • bootstrap 是应用程序的父上下文，加载优先级高于 application，主要用于从外部资源加载配置信息、对本地外部配置文件解密属性；
  • 两个上下文共用同一个环境；bootstrap 中的属性优先加载，默认不能被本地相同配置覆盖；
  • bootstrap 主要在 Spring Cloud 场景（配置中心等）中使用。

4.4 配置文件加载优先级

外部配置都可用于覆盖默认值，优先级从高到低大致为：命令行参数 > 系统环境变量 > 配置文件（properties / yml）。命令行参数示例：

java -jar xx.jar --server.port=9090

五、Starter 机制

5.1 概念与特点

Starter 是一组特殊的 Maven 依赖，利用传递依赖解析，把完成某一功能所需的常用 Jar 包聚合到一起，对外提供统一的依赖入口。主要特点：

  • 整合依赖：引入一个 Starter 即可获得某功能相关的整套依赖；
  • 自动配置：根据项目依赖与环境自动完成配置，提供大部分常用场景的默认行为；
  • 简化开发：预设大量配置，无须从零搭建应用；
  • 可扩展：保留可扩展接口与机制，按需添加或修改配置项。

5.2 工作原理（重点）

  1. Spring Boot 启动时，到依赖的 Starter 包中查找 META-INF/spring.factories 文件，按配置扫描所依赖的 Jar 包；
  2. 根据 spring.factories 加载对应的自动配置类（AutoConfiguration）；
  3. 依据 @Conditional 系列注解判断条件，满足条件才装配 Bean 并注入 Spring 上下文。

版本提示：Spring Boot 2.7 起，自动配置类注册方式逐步从 spring.factories 迁移到 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports；老版本项目仍以 spring.factories 为准。

5.3 常见官方 Starter

Starter 作用

spring-boot-starter-web Web 开发，含 Tomcat 与 Spring WebMVC
spring-boot-starter-aop Spring AOP 与 AspectJ 面向切面
spring-boot-starter-data-jpa JPA 支持（spring-data-jpa、spring-orm、Hibernate）
mybatis-spring-boot-starter MyBatis 支持（第三方）
spring-boot-starter-data-redis Redis 支持
spring-boot-starter-jdbc JDBC 数据库支持
spring-boot-starter-mail 邮件发送
spring-boot-starter-security Spring Security 安全框架
spring-boot-starter-validation 参数校验
spring-boot-starter-amqp AMQP 消息队列集成
spring-boot-starter-quartz Quartz 定时调度框架

spring-boot-starter-logging 默认日志框架 Logback

除官方 Starter 外，社区也提供大量第三方 Starter，使用前确认其维护活跃度与版本兼容性。

5.4 兼容 XML 配置

Spring Boot 推荐零 XML 配置，但特殊要求下仍可通过 @ImportResource 加载传统 XML 配置文件：

@ImportResource({"classpath:some-context.xml", "classpath:another-context.xml"})
@SpringBootApplication
public class SpringbootApplication { ... }

六、外部配置与属性注入

6.1 四种读取配置的方式

  1. @PropertySource：指定额外的 properties 配置文件；
  2. @Value：逐个注入单个属性；
  3. Environment：通过环境对象按 key 读取属性；
  4. @ConfigurationProperties：类型安全地把一批属性绑定到 Bean。

6.2 @Value 注入单个属性

在 application.properties 中定义属性后，直接用 @Value 注入：

book.name=springboot
book.author=demo
@Value("${book.name}")
private String bookName;

6.3 类型安全配置 @ConfigurationProperties

通过 @ConfigurationProperties 把配置文件属性与一个 Bean 的字段关联，实现类型安全绑定；用 prefix 指定配置前缀，必要时用 locations 指定 properties 文件位置，Bean 可直接 @Autowired 注入使用：

@Data
@ConfigurationProperties(prefix = "book")
public class BookProperties {
    private String name;
    private String author;
}

七、日志配置

7.1 默认日志框架

Spring Boot 支持 JUL、Log4J、Log4J2、Logback 作为日志框架，控制台与文件输出均已预先配置；默认使用 Logback。

日志级别从低到高：TRACE < DEBUG < INFO < WARN < ERROR（FATAL 属于 Log4j 体系，Logback 标准级别不含 FATAL）。

7.2 基础日志配置

在 application.properties 中按包名配置级别、指定日志文件：

logging.level.org.springframework.web=DEBUG
logging.file.name=logs/app.log

7.3 logback-spring.xml 常用结构

在 resources 下新建 logback-spring.xml 即自动生效，常用标签与组件：

  • contextName：日志上下文名称，区分不同应用的记录；
  • property：定义变量，之后用 ${name} 引用；
  • logger：设置某个包或类的日志级别与指定 Appender；
  • root：根 Logger，只有一个 level 属性；
  • appender：负责日志输出的组件。

常用 Appender：

  • ConsoleAppender：输出到控制台；
  • FileAppender：输出到文件；
  • RollingFileAppender：滚动记录文件，满足条件后切换到新文件，是 FileAppender 的子类。

过滤器（filter）返回三种枚举值：DENY 日志立即抛弃；NEUTRAL 交给下一个过滤器继续处理；ACCEPT 立即处理，不再经过剩余过滤器。常用过滤器：

  • ThresholdFilter：临界值过滤器，级别低于临界值则拒绝；
  • LevelFilter：按具体级别过滤，匹配与不匹配分别配置接收/拒绝行为。

八、Profile 多环境配置

Profile 用于针对不同环境提供不同配置，全局 Profile 文件命名为 application-{profile}.properties，例如 application-prod.properties。通过 application.properties 中的 spring.profiles.active 指定生效的 Profile：

spring.profiles.active=dev

示例：开发环境端口 8888，生产环境端口 80，分别写在 application-dev.properties 与 application-prod.properties，切换 active 值即切换对应环境配置。

九、spring.factories 与 SPI 机制

9.1 概念与位置

spring.factories 是 Spring 中的配置文件，用于实现 SPI（Service Provider Interface） 机制：通过配置方式注册 Spring 组件，无需在代码中显式声明。文件位置为 src/main/resources/META-INF/spring.factories，采用 Properties 格式。

9.2 工作原理

Spring 通过 SpringFactoriesLoader 加载并解析该文件：

  1. 扫描阶段：启动时扫描 classpath 下所有 Jar 包中的 META-INF/spring.factories；
  2. 解析阶段：解析文件中的键值对配置；
  3. 加载阶段：按接口类型加载对应的实现类；
  4. 实例化阶段：通过反射创建实现类实例。

9.3 主要应用场景

  • 自动配置（AutoConfiguration）：Spring Boot 最核心的应用场景；
  • 应用上下文初始化器（ApplicationContextInitializer）；
  • 应用程序监听器（ApplicationListener）；
  • 失败分析器（FailureAnalyzer）。

9.4 自定义 Starter 实践要点

自定义 Starter 一般包含：自动配置类、配置属性绑定类、服务类，以及 spring.factories（或新版 .imports）注册；在其他项目引入该 Starter 后即可使用。实践建议：遵循命名规范、合理使用条件注解避免配置冲突、提供完整配置属性说明与测试。

十、运行原理与启动流程

10.1 查看自动配置报告

Spring Boot 自动配置源码位于 spring-boot-autoconfigure-xxx.jar。想知道当前项目启用了哪些自动配置，可用以下方式查看报告：

  • 运行 Jar 时加 --debug 参数：java -jar xx.jar --debug；
  • 在配置文件中设置 debug=true；
  • 在 IDE 启动参数中加 -Ddebug。

控制台中 positive matches 表示已启用的自动配置，negative matches 表示未启用的自动配置。

10.2 启动流程三阶段

  1. 准备阶段：加载应用初始设置、创建上下文，核心是 SpringApplication.run() 方法调用各初始化器完成准备工作；
  2. 上下文创建阶段：根据配置信息加载 Bean，核心是自动配置机制扫描 classpath 下的配置，自动加载并装配组件；
  3. 刷新上下文阶段：执行启动任务，包括创建 Web 服务器、加载配置、初始化组件，调用刷新机制装配核心组件；内嵌 Tomcat 就在此阶段启动。

细分的关键步骤依次为：初始化监听器 → 发布 ApplicationStartedEvent → 装配参数与环境、判断是否 Web 环境 → 触发 ApplicationEnvironmentPreparedEvent → 按配置决定是否打印 Banner → 创建对应类型的 ApplicationContext → 装配上下文环境变量、注册初始化器与 Bean 名生成器 → 发布 ApplicationPreparedEvent → 注册启动参数与 Banner、加载资源 → 调用各 RunListener 的 contextLoaded() → 调用 refresh() 装配 BeanFactory 等核心组件 → 遍历执行 CommandLineRunner → 发布 ApplicationReadyEvent，服务就绪。

10.3 开启 Spring Boot 特性的方式

  1. 继承 spring-boot-starter-parent 项目；
  2. 导入 spring-boot-dependencies 依赖（不继承 parent 时的替代方式）。

十一、小结

  • Spring Boot 用“习惯优于配置”把依赖聚合、默认装配、内嵌容器打包成开箱即用的工程，核心价值是降低搭建与部署成本；
  • @SpringBootApplication 是组合注解，自动配置由 @EnableAutoConfiguration 驱动；
  • Starter 通过 spring.factories（新版 .imports）+ @Conditional 条件注解完成 Bean 装配；
  • 配置注入有 @Value、@ConfigurationProperties、Environment、@PropertySource 四种方式，多环境用 Profile 切换；
  • 理解启动三阶段与自动配置报告（positive / negative matches），是排查“某 Bean 为什么没装配”的入口。
