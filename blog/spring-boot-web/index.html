一、Web 开发支持

Spring Boot 通过 spring-boot-starter-web 提供 Web 开发支持：它带来内嵌 Tomcat 与 Spring MVC 依赖。Web 相关的自动配置位于 spring-boot-autoconfigure 包下的 org.springframework.boot.autoconfigure.web 目录。

从包内类名可以看出两类职责：

  • ServerPropertiesAutoConfiguration / ServerProperties：自动配置内嵌服务器；
  • HttpEncodingAutoConfiguration / HttpEncodingProperties：自动配置 HTTP 编码。

其余类还覆盖错误处理（ErrorController、ErrorAttributes、ErrorViewResolver）、消息转换器（HttpMessageConverters、JacksonHttpMessageConvertersConfiguration、GsonHttpMessageConvertersConfiguration）、静态资源链、文件上传（MultipartAutoConfiguration、MultipartProperties）等。

二、Thymeleaf 模板引擎

2.1 为什么推荐 Thymeleaf

Spring Boot 提供多种模板引擎，推荐使用 Thymeleaf，因为它对 Spring MVC 有完善支持。不建议使用 JSP：JSP 在内嵌 Servlet 容器（内嵌 Tomcat、Jetty）中以 Jar 形式运行存在限制。

Thymeleaf 是一个面向 XHTML/XML/HTML5 的 Java 模板引擎，可作为 MVC Web 应用的 View 层，并通过额外模块与 Spring MVC 集成，完全替代 JSP。

2.2 基础语法

  • 命名空间：页面通过 xmlns:th="http://www.thymeleaf.org" 引入，需要动态处理的元素以 th: 为前缀；
  • 静态资源：用 @{} 引入 CSS、JS 等静态文件；
  • 访问 Model 数据：用 ${} 访问 Model 属性，与 JSP EL 类似；
  • 迭代：用 th:each 循环集合，迭代元素在表达式中访问其属性；
  • 条件判断：用 th:if 判断，支持 >、<、>=、<=、==、!=，条件中可使用 Spring EL 表达式；
  • 在 JS 中访问 Model：给 <script> 加 th:inline="javascript"，通过 [[${}]] 取值；
  • 行内事件：用 th:onclick 拼接点击方法与属性值。

常见表达式片段：

<!-- 引入静态资源 -->
<link rel="stylesheet" th:href="@{/css/app.css}">

<!-- 取值 -->
<span th:text="${person.name}"></span>

<!-- 迭代 -->
<div th:each="person : ${people}">
    <span th:text="${person.name}"></span>
</div>

<!-- 条件判断 -->
<div th:if="${not #lists.isEmpty(people)}">列表非空</div>

<!-- JS 内联取值 -->
<script th:inline="javascript">
    const name = /*[[${person.name}]]*/ 'default';
</script>

2.3 与 Spring MVC 集成原理

在 Spring MVC 中集成模板引擎需要定义 ViewResolver，ViewResolver 再解析出具体的 View。传统 JSP 用 InternalResourceViewResolver 配合 JstlView；Thymeleaf 同样提供了对应的 ThymeleafView 与 ThymeleafViewResolver，并由 SpringTemplateEngine 驱动模板渲染，TemplateResolver 负责模板前缀、后缀等通用配置。

2.4 Spring Boot 的自动配置

Spring Boot 通过 org.springframework.boot.autoconfigure.thymeleaf 包完成自动配置：

  • ThymeleafAutoConfiguration：自动配置集成所需 Bean，包括 TemplateResolver、TemplateEngine、ThymeleafViewResolver；
  • ThymeleafProperties：绑定以 spring.thymeleaf 开头的配置项，提供默认值。

2.5 实战步骤

  1. 引入依赖：spring-boot-starter-thymeleaf 会自动包含 spring-boot-starter-web：
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
  1. 编写 JavaBean：用于在模板页面展示数据；
  2. 放置静态文件：脚本、样式、图片等放在 src/main/resources/static 下；
  3. 编写页面：按默认规则，模板页面放在 src/main/resources/templates 下，新建 index.html；
  4. 准备数据：在 Controller 方法中把数据放入 Model（也可放在入口类演示）；
  5. 运行访问：启动后通过对应路径访问页面。

三、FreeMarker 模板引擎

3.1 基本概念

FreeMarker 是基于 Java 的模板引擎，用于生成动态内容（HTML 网页、邮件、配置文件、源代码等）。.ftl 文件包含静态文本与 FreeMarker 模板指令，模板与数据模型结合后生成最终输出。

  • 模板：包含静态内容与动态占位符的文本文件（.ftl）；
  • 数据模型：填充占位符的数据结构（Java 对象、Map、List 等）；
  • 输出：模板与数据结合后生成 HTML、XML、文本等最终内容。

3.2 使用场景

  • 生成 HTML 页面：后端数据填充到 .ftl 模板生成用户界面；
  • 生成电子邮件：动态插入用户信息生成邮件正文；
  • 生成配置文件：按环境生成 XML、JSON、Properties；
  • 代码生成：由模板生成源代码、SQL 脚本等。

3.3 优点

  • 分离逻辑与表现：模板专注展示，Java 代码专注业务；
  • 灵活性高：支持条件判断、循环、宏等高级功能；
  • 性能较好：模板解析渲染速度较快；
  • 易于集成：可与 Spring 等主流框架无缝集成。

四、Web 相关自动配置

4.1 ViewResolver 自动配置

查看 WebMvcAutoConfiguration 与 WebMvcProperties 源码，可以看到 Spring Boot 提供的视图解析配置：

  • BeanNameViewResolver：Controller 方法返回字符串视图名时，按 Bean 名称查找对应的 View 来渲染；
  • InternalResourceViewResolver：常用的视图解析器，通过前缀、后缀与方法返回的视图名拼接出实际页面路径。

4.2 静态资源自动配置

类路径目录：类路径下 /static、/public、/resources、/META-INF/resources 目录中的静态文件直接映射为 /**，可通过 http://localhost:8080/** 访问。

WebJars：把常用脚本框架封装成 Jar 包，/META-INF/resources/webjars/ 下的静态文件映射为 /webjars/**。

4.3 Converter 与 Formatter

只要定义了 Converter、GenericConverter、Formatter 接口实现类的 Bean，这些 Bean 会自动注册到 Spring MVC 中。

4.4 HttpMessageConverters

新增自定义 HttpMessageConverter 时，只需定义一个 HttpMessageConverters 类型的 Bean，在其中注册自定义转换器即可：

@Bean
public HttpMessageConverters customConverters() {
    HttpMessageConverter<?> customConverter1 = new CustomConverter1();
    HttpMessageConverter<?> customConverter2 = new CustomConverter2();
    return new HttpMessageConverters(customConverter1, customConverter2);
}

4.5 静态首页

把静态首页 index.html 放在以下任一目录，访问应用根路径时会直接映射：

  • classpath:/META-INF/resources/index.html
  • classpath:/resources/index.html
  • classpath:/static/index.html
  • classpath:/public/index.html

4.6 自定义静态资源与 WebMvc 配置

  • 静态资源映射可在 application.yml 中配置；
  • 需要额外 MVC 配置时，定义配置类并实现 WebMvcConfigurer 接口，覆盖对应方法即可。

4.7 接管 Spring Boot 的 Web 配置

  • 完全接管：默认 MVC 配置不满足需求时，配置类加 @EnableWebMvc 实现完全自控的 MVC 配置；
  • 保留默认、追加配置（推荐）：不想覆盖 Spring Boot 自动配置时，实现 WebMvcConfigurer 接口补充自定义配置。重写的 addViewControllers 等方法不会覆盖 WebMvcAutoConfiguration 中的同名逻辑，自定义配置与自动配置同时生效。

版本提示：早期教程中的 WebMvcConfigurerAdapter 在 Spring 5.0 已废弃，直接实现 WebMvcConfigurer 接口即可。

4.8 注册 Servlet、Filter、Listener

使用内嵌 Servlet 容器（Tomcat、Jetty）时，通过三个注册 Bean 把 Servlet、Filter、Listener 声明为 Spring Bean：

  • ServletRegistrationBean：注册 Servlet；
  • FilterRegistrationBean：注册 Filter；
  • ServletListenerRegistrationBean：注册 Listener。

五、内嵌 Tomcat 配置与替换

5.1 配置 Tomcat

Tomcat 相关属性定义在 ServerProperties 配置类中，在 application.properties / application.yml 配置即可。通用 Servlet 容器配置以 server 为前缀，Tomcat 特有属性以 server.tomcat 为前缀，例如端口、连接超时、访问路径等。

5.2 替换内嵌容器

Spring Boot 默认使用 Tomcat。要换成 Jetty 或 Undertow，只需调整 spring-boot-starter-web 的依赖：排除默认的 spring-boot-starter-tomcat，引入对应的容器启动器（如 spring-boot-starter-jetty）。

六、SSL 与 HTTPS 配置

6.1 基本概念

SSL 是为网络通信提供安全与数据完整性的安全协议，位于 TCP/IP 协议与应用层之间，对网络连接加密。B/S 应用通过 HTTPS 实现 SSL，HTTPS 可以理解为 HTTP 下加入 SSL 层，安全基础是 SSL。

6.2 生成自签名证书

使用 JDK 自带的 keytool（位于 JDK 的 bin 目录）生成自签名证书：

keytool -genkey -alias tomcat

按提示操作后，当前目录会生成 .keystore 证书文件。

6.3 Spring Boot 配置 SSL

把 .keystore 复制到项目根目录，在配置文件中指定证书类型、别名、密码与密钥库路径等，启动后即可通过 https:// 访问。

注意：自签名证书不被浏览器默认信任，仅用于本地开发测试；生产环境应使用受信任 CA 签发的证书。

6.4 HTTP 跳转 HTTPS

实现 HTTP 自动跳转 HTTPS，需要通过自定义 ServletWebServerFactory 添加一个 HTTP Connector 做重定向。启动类中配置的重定向端口要与配置文件中的端口一致，否则启动报错。

七、mkcert 本地证书

mkcert 是用于生成本地受信任 SSL/TLS 证书的开源工具，简化本地开发环境的证书创建与管理。

主要功能

  • 零配置：自动把根证书安装到系统信任存储，生成本地可信任证书；
  • 多域名/IP：支持多个域名与 IP 地址；
  • 跨平台：支持 Linux、macOS、Windows；
  • 高级功能：可生成客户端认证证书、ECDSA 密钥、PKCS#12 文件等。

适用场景：本地 Web 开发测试 HTTPS、API 测试模拟 HTTPS 请求、物联网设备安全通信测试。

注意事项

  • 不要用于生产环境：生成的自签名证书不被公共浏览器信任，生产环境应使用受信任 CA 签发的证书；
  • 证书有效期较短（如 365 天），需要定期更新。

八、证书格式与 Java Trust Store

8.1 PEM 文件

PEM（Privacy-Enhanced Mail）是常用的证书与密钥格式，存储加密证书、私钥、公钥或证书链。它是 ASCII 文本格式，通常以 Base64 编码表示，便于网络传输。

基本结构：标头（标识数据块类型）+ Base64 编码内容 + 尾部（标记结束）。常见标记：

  • 证书：-----BEGIN CERTIFICATE----- / -----END CERTIFICATE-----；
  • 私钥：-----BEGIN PRIVATE KEY----- / -----END PRIVATE KEY-----；
  • 公钥：-----BEGIN PUBLIC KEY----- / -----END PUBLIC KEY-----；
  • 证书链：多个证书块串联，首块为服务器证书，后续为 CA 签发的中间证书或根证书。

用途：SSL/TLS 证书存储、公钥/私钥存放、证书链管理。

8.2 PEM / DER / PKCS#12 区别

格式 特点 典型用途
PEM Base64 编码，人类可读文本，有明确起止标记，常用于 Linux/Unix 传输证书与密钥
DER PEM 的二进制版本，直接存储二进制数据 非文本环境存储
PKCS#12（.pfx/.p12） 存储证书与私钥组合，支持加密保护 密钥与证书交换，尤其 Windows 系统

8.3 Java Trust Store

Java 的 Trust Store 用于存储受信任证书，验证与远程服务 SSL/TLS 通信时的证书链。Java 默认使用 cacerts 文件，内置广泛信任的根证书，路径与 JDK/JRE 安装位置相关：

  • Linux/macOS：$JAVA_HOME/lib/security/cacerts；
  • Windows：$JAVA_HOME/jre/lib/security/cacerts（新版本 JDK 路径为 $JAVA_HOME/lib/security/cacerts）。

cacerts 是一个 keystore 文件，存储知名 CA（如 DigiCert 等）的根证书，用于校验服务器证书有效性。

九、小结

  • starter-web 带来内嵌容器与 Spring MVC，Web 自动配置集中在 autoconfigure.web 包下；
  • 模板引擎首选 Thymeleaf，Spring Boot 通过 ThymeleafAutoConfiguration 完成自动装配；FreeMarker 适合生成 HTML、邮件、配置文件与代码；
  • Web 自动配置覆盖视图解析、静态资源、Converter/Formatter、消息转换器与静态首页；保留默认配置时实现 WebMvcConfigurer 追加自定义项；
  • 内嵌容器可在 Tomcat、Jetty、Undertow 间替换；SSL/HTTPS 用于加密传输，本地开发可用 mkcert 生成受信任证书；
  • 证书格式分 PEM（文本）、DER（二进制）、PKCS#12（证书+私钥组合），Java 通过 cacerts 校验远端证书链。
