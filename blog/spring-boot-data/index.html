一、基本概念

Spring Data 是 Spring 用来解决数据访问问题的一揽子解决方案，属于伞形项目，涵盖大量关系型与非关系型数据库的数据访问方案，使开发者可以快速使用传统数据访问技术与新技术。后续文章会再展开 MyBatis、MyBatis-Plus 的整合。

二、整合 H2 数据库

H2 是一款轻量级 Java 内嵌数据库，支持内存模式与文件模式，适合本地开发、单元测试与演示场景。

2.1 添加依赖

引入 JPA 支持与 H2 数据库驱动（H2 以 runtime 作用域引入）：

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>

2.2 数据源配置

默认情况下，Spring Boot 会用用户名 sa、空密码连接内存数据库。可在 application.properties 或 YAML 中覆盖这些参数：

spring.datasource.url=jdbc:h2:mem:testdb
spring.datasource.username=sa
spring.datasource.password=
spring.datasource.driver-class-name=org.h2.Driver
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    username: sa
    password:
    driver-class-name: org.h2.Driver

内存数据库在应用重启后会丢失数据；改用基于文件的存储即可持久化，把 url 指向文件路径：

spring.datasource.url=jdbc:h2:file:./data/demo

2.3 初始化数据库

在 src/main/resources 下添加脚本：

  • schema.sql：建表语句；
  • data.sql：初始化示例数据。
-- schema.sql
CREATE TABLE IF NOT EXISTS countries (
    id   INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100)
);
-- data.sql
INSERT INTO countries (name) VALUES ('China'), ('Japan');

Spring Boot 会自动获取这些脚本，在嵌入式内存数据库（如 H2）中执行，适合测试或初始化。可通过 spring.sql.init.mode 控制初始化行为：

# always：始终执行；embedded：仅嵌入式库执行；never：禁用
spring.sql.init.mode=embedded

2.4 访问 H2 控制台

H2 自带嵌入式 Web 控制台，用于浏览库表与运行 SQL。默认不启用，需要在配置中打开：

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

启动应用后访问 http://localhost:8080/h2-console，用配置文件中的凭证登录。连接后页面左侧列出所有表，右侧有 SQL 查询输入框，控制台带 SQL 关键字自动补全，适合直观检查数据或直接执行原始 SQL。

控制台相关配置：

# 控制台路径，相对于应用地址与端口
spring.h2.console.path=/h2-console
# 是否输出 Trace 信息
spring.h2.console.settings.trace=false
# 是否允许远程访问（生产环境务必关闭）
spring.h2.console.settings.web-allow-others=false

注意：web-allow-others 仅在本机开发时考虑放开；生产环境不要暴露 H2 控制台。

三、整合 Druid 数据源

3.1 默认数据源与切换方式

Spring Boot 各版本默认数据源：

  • 2.0 之前：org.apache.tomcat.jdbc.pool.DataSource；
  • 2.0 及之后：com.zaxxer.hikari.HikariDataSource。

切换数据源只需在配置文件中通过 spring.datasource.type 指定 DataSource 接口实现类：

spring.datasource.type=com.alibaba.druid.pool.DruidDataSource

3.2 Druid 的主要优势

  • 监控能力强：内置 Web 控制台实时查看连接池状态、SQL 执行时间/次数/错误统计、慢 SQL 与执行分布；提供活跃/空闲连接数、等待线程数、事务提交回滚次数等统计信息；
  • 连接池性能好：较优的连接池算法降低获取开销，支持 PreparedStatement 缓存，具备智能连接回收机制，减少连接泄漏与 GC 压力；
  • 扩展功能丰富：SQL 防火墙（wall）、多数据源支持，便于实现读写分离、分库分表、多租户隔离；
  • 集成便捷：通过 Spring Boot Starter 自动配置，零侵入接入，兼容 Spring 事务管理。

3.3 常用配置项

Druid 配置以 spring.datasource.druid.* 为前缀，常用参数如下：

配置项 含义
name 多数据源时用于区分监控的名称
url 数据库连接地址，随数据库类型而定
username / password 连接用户名 / 密码（示例用占位符，勿填真实凭证）
driverClassName 驱动类名；不配置时 Druid 根据 url 自动识别
initialSize 初始化时建立的物理连接个数
maxActive 最大连接池数量
minIdle 最小连接池数量
maxIdle 已废弃，配置无效
maxWait 获取连接时最大等待时间（毫秒）；配置后默认启用公平锁，可用 useUnfairLock=true 切换非公平锁
poolPreparedStatements 是否缓存 PreparedStatement（PSCache）；MySQL 下建议关闭，Oracle 等支持游标的数据库提升明显
maxPoolPreparedStatementPerConnectionSize 单个连接的 PSCache 大小；大于 0 时自动开启 PSCache
validationQuery 检测连接是否有效的 SQL（常用 select 'x'）；为 null 时相关检测不生效
validationQueryTimeout 连接检测超时时间（秒）
testOnBorrow 申请连接时检测有效性，会降低性能
testOnReturn 归还连接时检测有效性，会降低性能
testWhileIdle 建议设为 true：空闲超阈值时才检测，不影响性能且保证安全
keepAlive minIdle 以内的空闲连接超过 minEvictableIdleTimeMillis 后执行保活操作
timeBetweenEvictionRunsMillis Destroy 线程检测连接的间隔时间，也是 testWhileIdle 的判断依据
minEvictableIdleTimeMillis 连接保持空闲而不被驱逐的最小时间
connectionInitSqls 物理连接初始化时执行的 SQL
exceptionSorter 数据库抛出不可恢复异常时抛弃连接
filters 别名方式配置扩展插件：stat 监控统计、wall SQL 防火墙、log4j/slf4j 日志
proxyFilters 类型为 List<Filter>；与 filters 同时配置时为组合关系，并非替换

3.4 使用 Druid Starter

Druid 官方提供了 Spring Boot 启动器，引入后即可自动装配，无须再写配置类注入 Bean。

1. 添加依赖：

<dependency>
    <groupId>com.alibaba</groupId>
    <artifactId>druid-spring-boot-starter</artifactId>
</dependency>

2. 编写配置：默认配置以 spring.datasource.druid.* 开头，直接在配置文件中填写即可：

spring:
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    url: jdbc:mysql://localhost:3306/demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: demo
    password: ${DB_PASSWORD:change-me}
    driver-class-name: com.mysql.cj.jdbc.Driver
    druid:
      initial-size: 5
      min-idle: 5
      max-active: 20
      max-wait: 60000
      test-while-idle: true
      validation-query: select 'x'
      filters: stat,wall

3. 启动测试：编写测试类或接口验证能否正常读取自定义配置。引入监控插件后，访问 http://localhost:8080/druid 可进入 Druid 默认监控控制台。

3.5 自动配置核心类：DruidDataSourceAutoConfigure

DruidDataSourceAutoConfigure 是 Druid 连接池在 Spring Boot 中的自动配置核心类，负责自动创建和配置 Druid 数据源。关键注解：

  • @ConditionalOnClass：只有 classpath 中存在 DruidDataSource 类时才激活自动配置，确保引入 Druid 依赖后才装配；
  • @AutoConfigureBefore：在 Spring Boot 默认的 DataSourceAutoConfiguration 之前执行，优先使用 Druid 配置覆盖默认数据源；
  • @EnableConfigurationProperties：启用配置属性绑定，DruidStatProperties 绑定 spring.datasource.druid.*，DataSourceProperties 绑定 spring.datasource.*。

核心配置方法负责创建主数据源，DruidDataSourceWrapper 作为内部类封装数据源实例。

3.6 动态数据源上下文：DynamicDataSourceContextHolder

DynamicDataSourceContextHolder 是动态数据源组件的核心工具类，用 ThreadLocal 存储和管理当前线程的数据源标识，保证多线程环境下各线程独立切换、互不干扰。

主要方法：

  • setDataSourceType(String dataSourceType)：把数据源 key 存入当前线程 ThreadLocal；
  • getDataSourceType()：获取当前线程绑定的数据源标识；
  • clearDataSourceType()：清除当前线程的数据源上下文，避免内存泄漏，操作完成后调用。

工作原理：该类通常配合 DynamicDataSource 与 AbstractRoutingDataSource 使用。执行数据库操作时，AbstractRoutingDataSource 调用 determineCurrentLookupKey()，内部通过 DynamicDataSourceContextHolder.getDataSourceType() 取出当前线程应使用的数据源标识，从而路由到目标数据源。这种设计支持运行时按业务需要灵活切换数据源，适用于读写分离、多租户等场景。

四、小结

  • Spring Data 是覆盖关系型与非关系型数据库的数据访问伞形方案；H2 适合本地开发与测试，分内存模式与文件模式，可通过 schema.sql/data.sql 自动初始化；
  • Spring Boot 2.0+ 默认 HikariCP，指定 spring.datasource.type 即可切换为 Druid；Druid 优势在监控、连接池性能、SQL 防火墙与多数据源支持；
  • Druid Starter 通过 spring.datasource.druid.* 自动装配，监控控制台默认挂在 /druid；
  • 动态数据源基于 ThreadLocal 上下文 + AbstractRoutingDataSource 路由 key 实现，支撑读写分离、多租户等场景。
