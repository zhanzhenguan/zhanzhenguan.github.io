一、版本基线

1.1 先分清三个概念

  • Swagger：早期描述 REST API 的规范及工具生态，Swagger 2.0 是规范版本。
  • OpenAPI：Swagger 规范捐赠后演进的名称，OpenAPI 3.x 是当前主流接口描述规范。
  • Swagger UI：根据 OpenAPI 描述文件生成网页界面，支持查看接口、填写参数、发送请求。
  • Springdoc OpenAPI：扫描 Spring MVC 控制器、DTO、注解，自动生成 OpenAPI 文档，并集成 Swagger UI。

一句话概括：springdoc 生成的是 OpenAPI 3 文档，展示用的仍然是 Swagger UI。不要把 springdoc 直接称为「Swagger 2.0」。

1.2 为什么不用 Springfox

Spring Boot 3 迁移到 Jakarta EE，Servlet 等 API 包名从 javax.* 变成 jakarta.*，Spring MVC 的路径匹配机制也变了。Springfox（springfox-swagger2、springfox-boot-starter）主要面向较早的 Spring 生态，在 Boot 3 项目中容易出现启动失败、文档页面异常。

所以 Boot 3 项目只用 springdoc 2.x，并且 不要额外引入任何 Springfox 依赖，也不要同时引入多个版本的 swagger-annotations，否则会出现注解类冲突。

1.3 版本兼容矩阵

Spring Boot 版本 springdoc 建议版本 说明
3.0.x 2.0.x ~ 2.1.x 按具体补丁版本验证
3.1.x 2.2.x 建议使用匹配的 2.2.x
3.2.x 2.3.x ~ 2.5.x 建议使用匹配的 2.3 ~ 2.5 系列
3.3.x 2.6.x 避免直接套用不匹配版本
3.4.x 2.7.x ~ 2.8.x 按官方兼容矩阵选择
3.5.x 2.8.x ~ 2.10.x 本教程采用 2.10.0

springdoc-openapi v2.10.0 Release Notes 写明：Spring Boot 3.5.x line (built on Spring Boot 3.5.16)，即该版本基于 Boot 3.5.16 构建，两者构建基线一致。依赖能下载不等于版本兼容，版本基线一定要先查官方资料再动手。

三、添加 Maven 依赖

3.1 pom.xml

只需要一个 springdoc-openapi-starter-webmvc-ui，它已经包含 OpenAPI 文档生成能力和 Swagger UI 页面，不需要再手动加 springdoc-openapi-starter-webmvc-api 或 swagger-ui 依赖。

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springdoc</groupId>
        <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
        <version>2.10.0</version>
    </dependency>
</dependencies>

3.2 依赖树检查

构建后跑一次依赖树：springdoc 只有 2.10.0 一个版本，swagger-annotations-jakarta 只有一个版本，没有 Springfox，也没有被手工覆盖的 Spring Web 组件。

3.3 保留方法参数名

maven-compiler-plugin 的 <parameters>true</parameters> 不能省。Spring Boot 3.2 起参数名发现机制有变化，未开启时文档中的参数名可能显示成 arg0、arg1：

<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <parameters>true</parameters>
    </configuration>
</plugin>

四、配置 Swagger UI

4.1 application.yml

springdoc:
  api-docs:
    enabled: true
    path: /v3/api-docs
  swagger-ui:
    enabled: true
    path: /swagger-ui.html
    operations-sorter: alpha
    tags-sorter: alpha
    display-request-duration: true
  # packages-to-scan: com.example.swagger.controller   # 启用分组时不要写全局扫描包，见第十三章

logging:
  charset:
    console: UTF-8

4.2 配置项含义

配置项 作用
springdoc.api-docs.enabled 是否启用 OpenAPI 文档接口
springdoc.api-docs.path JSON 文档地址
springdoc.swagger-ui.enabled 是否启用 Swagger UI
springdoc.swagger-ui.path UI 页面入口
operations-sorter 接口排序方式，alpha 表示按名称排序
tags-sorter 分组标签排序方式

默认访问地址：UI 为 http://localhost:8080/swagger-ui.html，JSON 为 /v3/api-docs，YAML 为 /v3/api-docs.yaml。若设置了 server.servlet.context-path，地址里要带上上下文路径。

4.3 生产环境关闭文档

生产环境按需关闭文档，用多环境配置落地：prod profile 下把 springdoc.api-docs.enabled 和 springdoc.swagger-ui.enabled 都设为 false。实测业务接口 /api/users 仍返回 200，而 /v3/api-docs 和 /swagger-ui.html 都返回 404，符合预期。

五、启动类与全局 OpenAPI 信息

启动类没有任何特殊配置。用 @OpenAPIDefinition 定义文档标题、描述、版本和联系人：

@Configuration
@OpenAPIDefinition(
        info = @Info(
                title = "Demo API",
                description = "Spring Boot 接口文档示例",
                version = "v1",
                contact = @Contact(name = "demo")))
public class OpenApiConfig {
}

容易忽略的细节：@Configuration 不能省。官方 FAQ 指出，如果把 @OpenAPIDefinition 或 @SecurityScheme 挂在一个没有任何实现的类上，AOT/原生编译或类裁剪时这个类可能被优化掉，注解随之失效。

六、编写 DTO 与参数校验

@Schema 负责文档描述，@NotBlank / @Size / @Email 负责真实校验。注意 Boot 3 用的是 jakarta.validation.constraints，不是 javax。

public record UserCreateRequest(
        @NotBlank(message = "姓名不能为空")
        @Size(max = 50)
        @Schema(description = "用户姓名", example = "张三")
        String username,

        @Email(message = "邮箱格式不正确")
        @Schema(description = "邮箱")
        String email) {
}

响应 DTO、订单 DTO 与枚举同理，字段上用 @Schema 补充示例与约束。

七、用内存仓储让 CRUD 行为自洽

Controller 直接内存固定返回时，getById 无论传什么 ID 都返回张三、delete 是空实现，但注解里又声明了 404——演示文档生成没问题，但接口声明与真实行为对不上，用 Swagger UI 点一遍就会困惑。

实践中加一层线程安全的内存仓储，让新增可查、删除后查不到、不存在的 ID 真的返回 404。初始两条数据 ID 为 1001、1002，自增从 1003 开始。真实项目把这一层换成 JdbcTemplate / JPA / MyBatis 即可，Controller 不用改。

注解 作用 常见位置

九、补齐常用场景：搜索、文件上传、枚举

9.1 搜索与分页参数

/api/users/search 用多个 @RequestParam + @Parameter 描述查询参数，defaultValue 会直接体现在 Swagger UI 的输入框里。分页参数非法时抛 IllegalArgumentException。

9.2 文件上传

两个要点缺一不可：consumes = MediaType.MULTIPART_FORM_DATA_VALUE 和 MultipartFile + @RequestPart。实测生成的 OpenAPI 文档中，该操作的 requestBody.content 包含 multipart/form-data，Swagger UI 会渲染出文件选择框。

9.3 枚举在文档中的实际效果

和直觉不一致的一点：springdoc 2.10.0 把枚举内联到字段属性里。components.schemas 里没有 OrderStatus 这个 key，但枚举值一个不少地出现在 OrderResponse.status.enum 中，Swagger UI 里照样是下拉选择。写自动化校验脚本时按这个结构断言，别想当然去找独立枚举 Schema。

十、统一异常处理

本项目保持成功响应为业务 DTO 本身，只把异常响应统一成 ApiError。

10.1 状态码映射

场景 HTTP 响应
空姓名 / 非法邮箱 / 姓名超长 400 fieldErrors 含具体字段提示
ID 传 abc、缺 file 部件、非法 JSON、分页参数越界 400 统一错误体
用户 / 订单不存在 404 code=404
/favicon.ico 等静态资源 404 不打印 ERROR 堆栈

最后一条是专门加的防御：Spring Boot 3 里访问不存在的静态资源会抛 NoResourceFoundException，如果没有显式处理，容易被兜底逻辑变成 500 并打一屏 ERROR 堆栈。显式映射成 404 后，启动日志能保持干净：

@ExceptionHandler(NoResourceFoundException.class)
public ResponseEntity<Map<String, Object>> staticNotFound(NoResourceFoundException e) {
    return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(Map.of("code", 404, "message", "资源不存在"));
}

十一、配置 JWT Bearer Token 认证

11.1 声明安全方案

安全方案配置类同样带 @Configuration：

@Configuration
@SecurityScheme(
        name = "Bearer Authentication",
        type = SecuritySchemeType.HTTP,
        scheme = "bearer",
        bearerFormat = "JWT")
public class SecurityConfig {
}

11.2 在接口上声明

受保护接口或 Controller 类上加 @SecurityRequirement(name = "Bearer Authentication")。启动后 Swagger UI 右上角出现 Authorize 按钮，输入令牌后，受保护接口的调试请求会带上 Authorization 请求头。

11.3 安全提醒

Authorize 只负责在调试请求中携带凭证，不会替代 Spring Security 的身份认证和权限校验。若项目为聚焦文档本身没引入 Spring Security，受保护接口无需令牌也能访问。不要把真实生产 Token 写进源码或公开文档。

十二、Spring Security 放行文档地址

若项目集成 Spring Security，需要按实际安全策略放行文档资源，否则页面会出现 401/403。两点说清楚：

  1. 本项目没有引入 spring-boot-starter-security，放行代码只是条件性示例；照搬进本项目会因为缺少相关类而编译失败。
  2. 放行的是文档资源，业务 API 仍按项目规则鉴权。生产环境是否对外开放 Swagger UI 由安全策略决定；若使用 OAuth2、网关或自定义过滤器，还要检查对应认证链路。

十三、分组管理多个模块

13.1 GroupedOpenApi 配置

大型项目通常按模块拆分文档，用 GroupedOpenApi 分别生成：

@Bean
public GroupedOpenApi userApi() {
    return GroupedOpenApi.builder()
            .group("用户模块")
            .pathsToMatch("/api/users/**")
            .build();
}

@Bean
public GroupedOpenApi orderApi() {
    return GroupedOpenApi.builder()
            .group("订单模块")
            .pathsToMatch("/api/orders/**")
            .build();
}

分组文档通过 /v3/api-docs/{group} 访问，Swagger UI 会读取 swagger-config 并在右上角展示分组下拉框。

13.2 实测踩坑：全局 packages-to-scan 让分组失效

一次端到端验证中有两项分组失败：两个分组都返回了全部路径，tags 里同时出现两个模块，隔离完全没生效。排查过程：

  1. 先确认分组 Bean 确实注册了——swagger-config 里两个分组都在，Bean 没问题；
  2. 抓分组文档发现 paths 是全量，说明 Bean 生效但过滤条件没起作用；
  3. 怀疑对象就是 application.yml 里那行全局 springdoc.packages-to-scan；
  4. 对照实验：把全局配置注释掉，重新打包重启，再抓两个分组文档，隔离恢复。

结论：一旦定义了 GroupedOpenApi，全局 springdoc.packages-to-scan 会与分组自身的 packagesToScan 叠加，导致分组过滤失效。全局配置写在 yml 的 springdoc.packages-to-scan 上，分组配置写在 GroupedOpenApi 的 packagesToScan 里，两处单独看都没错，放同一个项目里就会打架。

处理方式二选一：

  • 需要分组时，不启用全局 packages-to-scan（本项目采用，配置保留为注释说明）；
  • 确实需要全局扫描包时，分组改用 pathsToMatch("/api/users/**") 这类按路径过滤的条件，不要同时依赖 packagesToScan。

13.3 分组访问注意点

分组名用中文时，URL 里要编码。浏览器和 Swagger UI 会自动处理，写脚本或命令行调用时记得编码。

十五、常见问题与排查

问题现象 原因与处理
启动时报 javax.servlet 或类找不到 混入旧版 Springfox 或 javax 依赖。移除 Springfox，Boot 3 用 jakarta API 和 springdoc 2.x
Swagger UI 页面 404 依赖未引入、路径配置错误或 context-path 遗漏。检查 starter、端口与 springdoc.swagger-ui.path
页面打开但接口列表为空 Controller 未被扫描或分组路径不匹配。检查启动类包结构、组件扫描与分组配置

OpenAPI JSON 返回 500 类型解析失败、循环引用或自定义转换器问题。查看服务端堆栈，检查 DTO、泛型与 Jackson 配置
参数名称未正确显示 编译时未保留参数名。maven-compiler-plugin 开启 <parameters>true</parameters>
上传文件参数显示异常 未声明 multipart 或参数类型不合适。用 MultipartFile 配合 consumes
JWT 无法调试 未配置 SecurityScheme 或接口未声明 SecurityRequirement。配置 Bearer Scheme，检查请求头与后端鉴权
两个分组返回全部接口 全局 packages-to-scan 与分组 packagesToScan 叠加。二选一，见 13.2
找不到独立的枚举 Schema springdoc 2.10.0 把枚举内联到字段属性。检查 OrderResponse.properties.status.enum，见 9.3
/favicon.ico 触发 500 + ERROR 堆栈 NoResourceFoundException 落到兜底异常。显式映射 404，见 10.3

十六、生产环境使用建议

  • 不要默认在公网生产环境开放 Swagger UI，按环境关闭或增加访问控制（本项目已给出 prod profile 示例）。
  • 开发、测试、生产使用不同配置，生产可设置 springdoc.api-docs.enabled=false、springdoc.swagger-ui.enabled=false。
  • 文档中不要出现真实密码、密钥、Token、身份证号、手机号等敏感信息。
  • 接口说明应描述真实业务语义、参数约束、错误码和权限要求，不要只依赖自动生成。
  • 统一响应结构、分页结构和异常响应应通过 DTO / @Schema 注解清晰描述。
  • 对外 API 建议把 OpenAPI 文档纳入版本管理和发布流程，避免接口实现与文档长期不一致。
  • 内存仓储仅用于演示，真实项目应替换为持久层，并补充事务、并发控制和权限校验。

十七、Swagger 2 与 Springdoc 注解对照

旧版 Swagger 2 注解 Springdoc / OpenAPI 3 注解
@Api @Tag
@ApiOperation @Operation
@ApiParam @Parameter
@ApiModel @Schema
@ApiModelProperty @Schema
@ApiResponse（旧包） io.swagger.v3.oas.annotations.responses.ApiResponse

迁移时不要只做类名替换。注解包名、响应结构、参数位置、枚举、文件上传和安全定义的语义都要重新核对。新项目直接用 io.swagger.v3.oas.annotations 下的注解。

十八、小结

  1. 版本基线先查官方再动手：Boot 3.5.x 配 springdoc 2.10.0，官方 Release Notes 明确构建基线是 3.5.16。
  2. 文档声明要和接口行为一致：既然写了 404，就真的让不存在的资源返回 404；既然写了 multipart，就真的用 MultipartFile。
  3. 配置项之间会互相影响：全局 packages-to-scan 和 GroupedOpenApi.packagesToScan 叠加导致分组失效，是实测最有价值的发现，只看单章文档很难提前发现。
