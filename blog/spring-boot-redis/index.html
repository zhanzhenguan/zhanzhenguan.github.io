一、引入依赖与客户端选择

引入官方启动器即可：

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>

该 Starter 内部包含 spring-data-redis 与 lettuce-core 两个核心包，因此 Spring Boot 默认使用 Lettuce 客户端。想换成 Jedis，需要排除 Lettuce 依赖，再引入 Jedis 客户端与连接池实现。

自动配置原理

Spring Boot 预设的自动配置类都在 spring-boot-autoconfigure 包中，Redis 对应的是 RedisAutoConfiguration。它内部引入 LettuceConnectionConfiguration 与 JedisConnectionConfiguration 两个配置类，分别对应两个客户端；两者都用条件注解判断 classpath 中是否存在对应客户端类。项目引入了 lettuce-core 而没有 Jedis 依赖时，Lettuce 配置条件成立被加载，Jedis 配置不成立不加载，于是默认生效 Lettuce。

二、连接配置

版本前缀：Spring Boot 2.x 使用 spring.redis.*；3.x 迁移到 spring.data.redis.*。下面示例按 2.x 前缀书写。

2.1 单机配置

spring:
  redis:
    host: localhost
    port: 6379
    database: 0
    password: ${REDIS_PASSWORD:change-me}
    timeout: 2000ms

Redis 6.0+ 支持用户名，可通过 username 配置。

2.2 集群配置

集群模式下配置节点列表与重定向次数：

spring:
  redis:
    cluster:
      nodes: host1:6379,host2:6379,host3:6379
      max-redirects: 3
    password: ${REDIS_PASSWORD:change-me}

2.3 连接池配置

客户端是 Lettuce 时，连接池配置挂在 spring.redis.lettuce.pool 下；用 Jedis 则换成 spring.redis.jedis.pool。

spring:
  redis:
    lettuce:
      pool:
        max-active: 8
        max-idle: 8
        min-idle: 0
        max-wait: -1ms

关键点：仅在配置文件写连接池参数不会生效，还必须引入连接池依赖 commons-pool2；导入前后观察 RedisTemplate 底层连接池对象是否有值可以验证。

三、RedisTemplate 与五种数据结构

操作 Redis 主要使用 Spring Data Redis 提供的 RedisTemplate；纯字符串场景用特化的 StringRedisTemplate。RedisTemplate 封装了连接管理、序列化与异常处理，通过不同的 opsForXxx() 方法操作五种数据结构：

方法 数据结构
opsForValue() String 字符串
opsForList() List 列表
opsForSet() Set 集合
opsForZSet() ZSet 有序集合
opsForHash() Hash 哈希 
@Service
public class RedisService {

    private final StringRedisTemplate stringRedisTemplate;

    public RedisService(StringRedisTemplate stringRedisTemplate) {
        this.stringRedisTemplate = stringRedisTemplate;
    }

    public void setValue(String key, String value) {
        stringRedisTemplate.opsForValue().set(key, value, 30, TimeUnit.MINUTES);
    }

    public String getValue(String key) {
        return stringRedisTemplate.opsForValue().get(key);
    }
}

其他常用方法：hasKey(key) 判断键是否存在、keys(pattern) 按模式查键、getExpire(key) 获取剩余过期时间（秒，未设置过期返回 -1）、boundValueOps(key) 绑定指定键。

四、核心操作接口

4.1 RedisOperations

RedisOperations 是定义 Redis 操作的核心接口，提供模板化编程模型：开发者无需关心连接管理与异常处理，即可操作 String、Hash、List、Set、ZSet 等结构；支持事务与 Pipeline 批量操作，并通过泛型保证 Key/Value 类型安全。RedisTemplate 是它的主要实现。

4.2 ValueOperations

面向 String 简单键值对的操作接口，常用方法：

  • get(key)：取值，键不存在返回 null；
  • set(key, value) / set(key, value, timeout, unit)：写入，可带过期时间；
  • getAndDelete(key)：返回值并删除键；
  • increment(key, delta)：整数自增（delta 可正可负），键不存在则初始化为 delta；适合计数器、统计、限流；
  • decrement(key)：递减；
  • multiGet(keys)：批量取值；
  • getAndSet(key, value)：取旧值并写入新值。

4.3 BoundValueOperations

把操作绑定到某个固定 Key，后续调用无需反复传键名，支持链式调用，简化同一键的多次 set/get/append 操作。通过 redisTemplate.boundValueOps(key) 获取实例，适合计数器、对象缓存、动态开关等场景。

4.4 RedisCallback

RedisCallback 是底层回调接口，核心方法 doInRedis(RedisConnection connection)：在回调中直接拿到 RedisConnection，执行 RedisTemplate 高级方法未覆盖的复杂命令、事务或流水线。由 RedisTemplate.execute() 传入并在连接上执行，用于细粒度控制连接与批量操作。

五、缓存抽象

5.1 RedisCacheManager

RedisCacheManager 实现 Spring 的 CacheManager 接口，负责把缓存数据存入 Redis，并管理缓存的创建与配置。可通过 RedisCacheManager.create(connectionFactory) 或 builder(connectionFactory) 构建；支持默认配置、全局统一配置、按缓存名独立配置，可启用事务支持与统计，未显式配置的缓存会按默认配置动态创建。

5.2 RedisCacheConfiguration

RedisCacheConfiguration 是配置缓存行为的不可变配置类，采用建造者模式链式设置：

  • defaultCacheConfig()：获取默认配置；
  • entryTtl(Duration)：固定过期时间，也可换用 TTL 函数做动态过期（3.2+）；
  • disableCachingNullValues()：禁止缓存 null；
  • disableKeyPrefix()：禁用 Key 前缀；
  • enableTimeToIdle()：启用空闲时间过期（TTI）。

六、Lua 脚本与限流

6.1 限流算法选择

  • 固定窗口计数器：简单，但有窗口边界突刺问题；
  • 滑动窗口计数器：结果平滑，内存占用较高；
  • 令牌桶算法：允许一定突发流量；
  • 漏桶算法：流量整形，输出平滑。

滑动窗口兼顾平滑与实现成本，是常见的接口限流方案。

6.2 架构与原理

Redis 存储限流数据并利用原子性，Lua 脚本保证限流逻辑原子执行，Spring Boot 通过 AOP 注解方式接入。用 ZSet 存储每个请求的时间戳，Lua 脚本在一次执行内完成：移除过期记录 → 统计窗口内请求数 → 判断是否超限 → 写入新请求记录。

6.3 脚本执行：DefaultRedisScript

DefaultRedisScript 实现 RedisScript 接口，封装 Lua 脚本执行：scriptText/scriptSource 存放脚本内容或资源，sha1 用于脚本缓存，resultType 指定返回类型。可直接传入脚本文本，也可从 resources/lua/ 下加载脚本文件。

@Bean
public DefaultRedisScript<Long> rateLimitScript() {
    DefaultRedisScript<Long> script = new DefaultRedisScript<>();
    script.setScriptSource(new ResourceScriptSource(new ClassPathResource("lua/rate_limit.lua")));
    script.setResultType(Long.class);
    return script;
}

典型落地步骤：定义限流注解与类型枚举、限流异常类、脚本管理、Lua 脚本文件、工具类、AOP 切面、全局异常处理、Redis 配置与 Controller 示例。优点是原子性、高性能、策略灵活、注解易用、便于扩展；注意事务中切换与分布式场景的边界。

七、序列化机制与选型

存入 Redis 的对象以什么格式存储，由序列化器决定。RedisSerializer 接口定义 serialize(T) 与 deserialize(byte[]) 两个方法，负责 Java 对象与存储字节之间的转换。

7.1 默认行为

  • 存 String 时默认使用 StringRedisSerializer；
  • 存对象时 RedisTemplate 默认使用 JdkSerializationRedisSerializer（JDK 原生二进制序列化），结果不可读、排查困难，且对象必须实现 Serializable。

7.2 常见序列化器对比

序列化器 特点 适用场景
StringRedisSerializer 轻量高效，仅支持字符串，UTF-8 编码 Key/Value 都是字符串；非字符串对象会抛 ClassCastException
JdkSerializationRedisSerializer JDK 原生二进制，保持完整类型信息，不可读、体积较大 纯 Java 内部系统、复杂对象缓存
Jackson2JsonRedisSerializer Jackson 转 JSON，可读、跨语言；不带类型信息，反序列化需明确目标类型，结果更小 缓存固定类型对象（如 User、Order）
GenericJackson2JsonRedisSerializer JSON 中携带类型信息，反序列化可恢复原始类型，支持泛型与复杂对象 通用缓存服务，缓存多种类型对象
GenericToStringSerializer 任意对象转字符串，支持自定义转换逻辑，可读性好 自定义格式、跨语言读取
ProtoBufRedisSerializer Protobuf 紧凑二进制，高性能低带宽 高吞吐、带宽敏感场景

7.3 自定义 JSON 序列化配置

通常自建 RedisTemplate Bean，Key 用字符串序列化器，Value 用 JSON 序列化器：

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        Jackson2JsonRedisSerializer<Object> serializer =
                new Jackson2JsonRedisSerializer<>(Object.class);

        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(serializer);
        template.setHashKeySerializer(new StringRedisSerializer());
        template.setHashValueSerializer(serializer);
        return template;
    }
}

选型要点：固定类型、追求体积用 Jackson2JsonRedisSerializer；多类型通用缓存、需要自动恢复类型用 GenericJackson2JsonRedisSerializer；生产环境注意限制反序列化类型范围，避免安全问题。

八、自动配置类与配置属性

8.1 RedisAutoConfiguration

Redis 自动配置核心类，关键注解：

  • @Configuration(proxyBeanMethods = false)；
  • @ConditionalOnClass(RedisOperations.class)：classpath 存在 Redis 操作类时才装配；
  • @EnableConfigurationProperties(RedisProperties.class)：绑定配置属性；
  • @Import({LettuceConnectionConfiguration.class, JedisConnectionConfiguration.class})：导入两个客户端连接配置。

8.2 RedisProperties

@ConfigurationProperties 配置属性类，2.x 前缀 spring.redis，主要分组：

分组 主要属性
基础连接 host（默认 localhost）、port（默认 6379）、password、database（默认 0）、url
连接池 Pool max-active（默认 8）、max-idle（默认 8）、min-idle（默认 0）、max-wait（默认 -1 无限等待）
集群 Cluster nodes（host:port 列表）、max-redirects
哨兵 Sentinel master、nodes、password
超时/SSL timeout、connect-timeout、read-timeout、ssl

九、小结

  • 引入 spring-boot-starter-data-redis，默认 Lettuce 客户端；切换 Jedis 需更换依赖，由条件注解决定加载哪个连接配置；
  • 单机、集群、哨兵在 spring.redis（3.x 为 spring.data.redis）下配置；Lettuce 连接池挂 lettuce.pool，且必须引入 commons-pool2 才生效；
  • RedisTemplate 通过 opsForValue/List/Set/ZSet/Hash 操作五种结构，StringRedisTemplate 专做字符串；底层有 RedisOperations、ValueOperations、BoundValueOperations、RedisCallback 等接口分层；
  • 缓存用 RedisCacheManager + RedisCacheConfiguration 管理过期、序列化与 Key 前缀；Lua 脚本配合 ZSet 可实现原子的滑动窗口限流；
  • 序列化默认对象走 JDK 二进制不可读，生产常用 JSON 序列化器，按是否需要保留类型信息在 Jackson2Json 与 GenericJackson2Json 间选择。
