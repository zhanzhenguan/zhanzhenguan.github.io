MySQL 基础入门：分层架构、SQL 执行流程与 InnoDB/MyISAM 引擎对比

二、MySQL 架构概述

2.1 我们写的 SQL 去哪了

Java 侧通常通过 MyBatis / MyBatis-Plus 发出一条 SELECT ...，这条 SQL 到达 MySQL 之后，需要先理解 MySQL 的整体分层架构，才能说清它经历了什么。

2.2 整体架构：Server 层 + 引擎层

MySQL 采用分层架构，核心分两层：

  • Server 层：负责连接管理、SQL 解析、查询优化等，不依赖具体引擎，相当于「脑子」；
  • 存储引擎层：负责数据的实际存储和读取，采用插件式架构（像可插拔的 U 盘）。InnoDB 是目前的默认引擎，也是重点讨论对象。

类比：把 MySQL 想象成一个餐厅——Server 层是大堂经理（接待客人、理解需求、规划上菜顺序），存储引擎是后厨（真正烹饪食物）。大堂经理不管后厨用什么锅，只负责把顾客订单翻译成后厨能理解的指令。

2.3 一条 SELECT 的执行流程

SELECT * FROM user WHERE id = 1;

这条语句在 MySQL 内部的完整旅程：

Java 程序
  ↓ JDBC 驱动发送 SQL
连接器 —— 建立连接、验证用户名密码、检查权限
  ↓
分析器 —— 词法分析（识别 SELECT、FROM 等关键字）
        → 语法分析（检查 SQL 语法是否正确）
  ↓
优化器 —— 选择用哪个索引、决定 JOIN 顺序 → 生成执行计划
  ↓
执行器 —— 调用存储引擎接口，逐行读取数据
  ↓
返回结果给客户端

面试小贴士：MySQL 8.0 移除了查询缓存。一旦表有写操作，缓存就失效，高并发写入场景下维护缓存的成本反而比直接查还要大，这是个「好心办坏事」的设计。

2.4 一条 UPDATE 的完整旅程

查询只读不写，更新语句则涉及非常重要的日志机制。以 UPDATE user SET name = '张三' WHERE id = 1; 为例：

执行器找到 id=1 的行
  ↓
InnoDB 将数据页加载到 Buffer Pool（内存缓冲区）
  ↓
写入 undo log（记录旧值，用于回滚）
  ↓
修改 Buffer Pool 中的数据页（name 改成新值）
  ↓
写入 redo log buffer（记录某数据页的修改）
  ↓
写入 binlog（Server 层记录：该表该行字段从旧值变成新值）
  ↓
事务提交完成

Buffer Pool 是 InnoDB 的内存缓存区，相当于 Redis 之于数据库：数据先从磁盘读到内存，修改也在内存中完成，后台再慢慢刷回磁盘。这是数据库支撑高并发的关键设计之一。三类日志（undo / redo / binlog）的详细作用在后续日志与架构篇展开，这里先建立印象。

三、存储引擎对比：InnoDB vs MyISAM

3.1 为什么要关心存储引擎

建表语句里常见 ENGINE = InnoDB，就是指定存储引擎：

CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY,
  `name` VARCHAR(50)
) ENGINE = InnoDB;

MySQL 支持多种存储引擎，但 Java 开发绝大多数情况下都在和 InnoDB 打交道。

3.2 核心差异一览

特性 InnoDB MyISAM
事务支持 支持 ACID 不支持
锁粒度 基于索引的行级锁 只有表级锁
外键 支持 不支持
崩溃恢复 redo log 保证 数据可能丢失
MVCC（多版本） 支持 不支持
全文索引 MySQL 5.6+ 支持 原生支持
聚簇索引 数据按主键物理排序 数据和索引分开存储
COUNT(*) 效率 需要扫描索引 直接读表元数据，极快

3.3 为什么生产环境一律用 InnoDB

这是面试中的送分题，三个核心原因：

  1. 事务安全是第一需求：订单、支付等关键业务场景，没有事务的数据操作就像没有安全带的高速赛车——出事就是大事；
  2. 并发性能：行级锁意味着不同用户可以同时修改不同的行，互不干扰；MyISAM 的表级锁则是一人改表、全员排队；
  3. 崩溃恢复：服务器突然断电时，InnoDB 靠 redo log 能把已提交的数据找回来，MyISAM 只能依赖 luck。

一句话总结：MyISAM 适合的场景极其有限（只读日志表、数据仓库类场景），面向 Java 业务开发，选 InnoDB 就对了。

四、小结

学完本篇，应该能回答四个问题：MySQL 分几层架构、Server 层和引擎层分别负责什么；一条 SELECT / UPDATE 在内部经历了哪些步骤；InnoDB 比 MyISAM 强在哪里、为什么是默认选择；Buffer Pool 是做什么的。

三个最基础的认知：

  1. 分层是骨架：Server 层做连接、解析、优化、执行，引擎层负责实际存储，二者解耦、插件式可替换；
  2. 执行有顺序：SELECT 走连接器 → 分析器 → 优化器 → 执行器；UPDATE 在内存 Buffer Pool 上改，配合 undo/redo/binlog 保证可回滚与可恢复；
  3. 业务默认 InnoDB：事务、行锁、外键、崩溃恢复、MVCC 是它相对 MyISAM 的核心优势。
