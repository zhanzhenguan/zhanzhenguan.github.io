从零搭建我的 Astro 博客：从初始化到双仓库部署全流程

2022年6月8日 · 约 4 分钟 · 1503 字 #Astro#博客搭建#前端#自动化部署

这篇文章记录我这个博客是怎么一步步搭起来的：从初始化 Astro 项目，到内容模型、布局组件、常用功能接入，最后通过 GitHub Actions 自动部署到 GitHub Pages。整体偏向实战复盘，方便自己以后重建环境，也供有类似需求的朋友参考。

一、选型与整体架构

最终技术栈：

  • 框架：Astro 5（内容优先的静态站点框架，默认输出纯静态 HTML，体积小、首屏快）
  • 内容：Markdown 文章，集中存放在 src/content/blog/，由内容集合（Content Collection）统一校验
  • 检索：Pagefind 构建离线全文索引，生成静态搜索
  • 评论：Giscus，基于 GitHub Discussions
  • 订阅：@astrojs/rss 生成 RSS，@astrojs/sitemap 生成站点地图
  • 部署：双仓库模式，源码私有仓 + 产物公开仓，推代码后 Actions 自动构建发布

这里先说清楚双仓库的设计，它直接决定后面的目录和配置：

仓库 作用
blog-astro（私有） 存放源码、文章、组件、样式与工作流
zhanzhenguan.github.io（公开） 只放 dist/ 构建产物，作为 GitHub Pages 主页

产物仓是 <用户名>.github.io 主页仓库，站点挂在根路径，所以 Astro 配置里只写 site，不写 base。

二、初始化项目

前置环境：Node.js 22、npm、Git。

# 初始化 Astro 项目
npm create astro@latest

# 进入目录安装依赖
npm install

# 本地开发，默认带热更新
npm run dev

常用脚本（对应 package.json）：

npm run dev       # 本地开发
npm run build     # 构建产物 + 生成 Pagefind 索引
npm run preview   # 本地预览构建产物

其中 build 实际执行的是：

astro build && pagefind --site dist

先把站点构建到 dist/，再由 Pagefind 扫描产物生成离线搜索索引。

三、目录结构与内容模型

源码主要目录：

src/
├── components/     # 可复用组件（卡片、分页、社交链接、主题切换等）
├── layouts/        # 页面布局（BaseLayout.astro）
├── pages/          # 路由页面（首页、归档、标签、分类、文章详情等）
├── styles/         # 全局样式与主题变量
├── utils/          # 文章、标签等工具函数
└── content/blog/   # 所有 Markdown 文章

文章的字段在 src/content.config.ts 里用 Zod 定义并校验：

const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.coerce.date(),
    updatedDate: z.coerce.date().optional(),
    tags: z.array(z.string()).default([]),
    draft: z.boolean().default(false),
    cover: z.string().optional(),
    pinned: z.boolean().default(false),
    series: z.string().optional(),
    category: z.string().optional(),
  }),
});

写新文章时，只要在 src/content/blog/ 下新建 .md 文件，填好 frontmatter：

---
title: "文章标题"
description: "一句话摘要，显示在列表页和浏览器描述里"
pubDate: 2026-11-25
tags: [标签一, 标签二]
draft: false
category: 分类名
---

draft: true 可先存草稿不对外展示；pinned 控制首页置顶；series 用于把同系列文章串起来。

四、布局与组件

1. 基础布局

BaseLayout.astro 是所有页面的外壳，负责：

  • 引入全局样式、字体与背景图
  • 顶部导航（首页、分类、归档、标签、关于）
  • 暗色模式初始化脚本（避免刷新闪烁）
  • 抽屉式移动导航
  • 页面底部版权与社交链接

正文内容通过 <slot /> 注入到布局中。

2. 复用组件

抽出的可复用组件放在 src/components/：

  • PostCard.astro：首页与列表页的文章卡片（封面、标题、摘要、标签）
  • Pagination.astro：分页控件
  • ThemeToggle.astro：亮/暗主题切换按钮
  • SocialLinks.astro：GitHub、RSS 等社交入口

五、核心功能接入

1. RSS 与站点地图

RSS 用 @astrojs/rss 生成，sitemap 用 @astrojs/sitemap：

// astro.config.mjs
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://zhanzhenguan.github.io',
  integrations: [sitemap()],
});

2. Pagefind 静态搜索

Pagefind 在构建后扫描 dist/，生成纯静态的倒排索引，前端打开时按需查询，不需要独立搜索服务。页面里通过 <pagefind-modal-trigger> 触发搜索弹窗。构建脚本里的 pagefind --site dist 就是在做这件事。

3. Giscus 评论

评论接入 Giscus，数据存在对应仓库的 GitHub Discussions 里。在后台开启 Discussions 后，把仓库名、分类等配置填进评论组件即可，文章详情页底部自动渲染评论区。

4. 暗色模式

主题用 CSS 变量驱动：:root 定义浅色变量，[data-theme='dark'] 覆盖暗色变量。切换时只改 document.documentElement.dataset.theme，并把选择存到 localStorage；<head> 内联一小段脚本在首帧前读取主题，避免刷新时白屏闪烁。

5. 文章页辅助信息

文章详情页陆续补上了：

  • 目录（TOC）与阅读进度条
  • 阅读时长、发布日期、更新日期
  • 上一篇 / 下一篇导航
  • 面包屑、版权声明、相关文章推荐
  • 代码块 Shiki 双主题高亮与复制按钮

6. 图片与提示块

  • 文章图片支持点击放大的灯箱效果
  • Markdown 中的提示块（Callout）用于强调注意事项与踩坑记录

六、样式与主题

全局样式集中在 src/styles/global.css，按主题分组管理：

  • 颜色：文字、边框、卡片底色、强调色（accent）及其浅底色
  • 尺寸：容器最大宽度、阅读行宽、圆角、间距
  • 背景：浅色 / 暗色各一张背景图，配合半透明遮罩保证文字可读性

样式变量和组件解耦，换配色时主要改变量，不必动组件结构。

七、本地开发与构建

# 安装依赖
npm ci

# 本地开发
npm run dev

# 检查构建是否通过
npm run build

# 本地预览构建产物
npm run preview

每次改动后先本地 build 确认没有报错，再考虑推送；预览地址默认是本地端口，方便对比深浅色、移动端导航等效果。

八、双仓库自动部署

部署工作流在 .github/workflows/deploy.yml，触发条件是推送到私有源码仓的 master 分支，也支持在 Actions 页面手动触发。

流程如下：

  1. 检出私有仓源码
  2. 安装 Node 22 与依赖（npm ci）
  3. 执行 npm run build 生成 dist/
  4. 用 DEPLOY_TOKEN 克隆公开产物仓
  5. 清空旧产物（保留 .git 历史）
  6. 拷贝最新 dist/* 到产物仓
  7. 提交并推送到产物仓默认分支
on:
  push:
    branches: [master]
  workflow_dispatch:

DEPLOY_TOKEN 是一个有权限推送公开仓的 Personal Access Token，作为仓库 Secrets 配置；工作流本身只读取私有源码，不把 token 暴露到前端。

注意：产物仓是主页仓库，站点根路径访问，Astro 配置里不要额外写 base；如果挂在子路径下才需要配置 base。

九、日常写文章的节奏

  1. 在 src/content/blog/ 新建 Markdown 文件，填好 frontmatter
  2. 正文用标准 Markdown：标题、列表、代码块、引用、图片
  3. 本地 npm run dev 预览排版与效果
  4. npm run build 确认构建无报错
  5. 提交并推送到私有仓 master，Actions 自动构建发布到 Pages

十、Markdown 写作速查

正文支持常用 Markdown 语法，写文章时直接套用即可：

  • 行内代码：npm run dev
  • 代码块：
npm install
npm run dev
  • 加粗、斜体、链接
  • 无序列表：
    • 条目一
    • 条目二
  • 引用块也可以正常渲染

引用块用于补充说明或强调注意事项。

十一、小结

这套方案的核心思路是：Astro 负责内容渲染与静态产物，Pagefind 负责离线检索，Giscus 承担评论，GitHub Actions 把源码和产物两个仓库解耦。日常写作只需要关心 Markdown 内容，样式、检索、部署都由工程模板兜底。

如果以后要扩展，可以再考虑访问统计、友链、i18n、PWA 等方向；当前版本优先保证写作体验、页面性能和部署稳定。
