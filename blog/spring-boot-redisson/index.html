一、Redisson 基本概念

Redisson 是一个基于 Redis 的 Java 分布式对象和服务框架，可以理解为 Redis Java 客户端的增强版：在基础命令封装之上，提供一整套面向对象的分布式能力。

核心功能

  • 并发控制工具：分布式锁、信号量、计数器等；
  • 分布式集合：分布式 Map、Set、List 等；
  • 分布式对象存储与缓存；
  • 异步与反应式编程接口。

主要优势

  • 简化 Redis 操作，提供面向对象 API；
  • 内置连接池管理与故障转移；
  • 支持集群、哨兵、单机等多种部署模式；
  • 自动序列化/反序列化。

常用场景：分布式锁、缓存管理、分布式会话存储、消息队列与发布订阅。

二、整合步骤

2.1 添加依赖

引入 Redisson 的 Spring Boot 启动器：

<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson-spring-boot-starter</artifactId>
</dependency>

2.2 连接配置

连接信息可写在 application.yml，也可通过配置类以编程方式组装 Config。按部署模式选择对应配置：

  • 单机模式：useSingleServer()；
  • 集群模式：useClusterServers()；
  • 哨兵模式：useSentinelServers()；
  • 主从模式：useMasterSlaveServers()。

单机模式配置类示例：

@Configuration
public class RedissonConfig {

    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer()
                .setAddress("redis://localhost:6379")
                .setPassword("${REDIS_PASSWORD:change-me}")
                .setDatabase(0);
        return Redisson.create(config);
    }
}

2.3 服务类使用

注入 RedissonClient 后即可存取对象、获取分布式锁：

@Service
public class RedissonService {

    private final RedissonClient redissonClient;

    public RedissonService(RedissonClient redissonClient) {
        this.redissonClient = redissonClient;
    }

    // 字符串/对象存取
    public void setBucket(String key, Object value) {
        RBucket<Object> bucket = redissonClient.getBucket(key);
        bucket.set(value, 30, TimeUnit.MINUTES);
    }

    public Object getBucket(String key) {
        return redissonClient.<Object>getBucket(key).get();
    }

    // 分布式锁
    public void doWithLock(String lockKey) {
        RLock lock = redissonClient.getLock(lockKey);
        try {
            lock.lock();
            // 业务逻辑
        } finally {
            lock.unlock();
        }
    }
}

之后编写 Controller 暴露字符串操作与对象操作接口进行测试即可。

三、核心接口 RedissonClient

RedissonClient 是 Redisson 的核心入口接口，代表一个 Redis 客户端连接实例，所有分布式对象都通过它创建。接口提供同步、异步与响应式三种调用方式，操作均为线程安全。

3.1 核心职责

  • 连接管理：维护与 Redis 的连接池；
  • 对象工厂：创建各类分布式对象（锁、集合、队列等）；
  • 序列化：统一管理 Java 对象编解码；
  • 命令执行：底层封装 Redis 命令发送。

3.2 常用方法

方法 返回类型 说明
getLock(name) RLock 可重入锁，同一线程可重复加锁，默认看门狗自动续期
getBucket(name) RBucket 单个对象存取，最常用的简单 KV 操作
getMap(name) RMap<K, V> 分布式 Map

3.3 生命周期与定位

RedissonClient 应单例使用：全局共享一个实例，不要频繁创建/销毁。相比 Jedis/Lettuce 偏底层命令封装，Redisson 在其上提供了更高层的分布式对象与并发工具抽象。

四、RBucket 分布式对象

RBucket 是 Redisson 中最基础的分布式对象接口，面向对象地封装 Redis 的 String 类型，可存储任意 Java 对象，内部自动完成序列化/反序列化。

核心功能：存储与获取 Java 对象、自动处理序列化、支持过期时间、提供原子性操作。

主要方法：

  • get()：获取值；
  • set(value)：设置值；
  • 可在 set 时指定过期时间。

特点：支持任意 Java 对象类型、线程安全的分布式操作、支持异步与反应式模式、自动管理 Redis 连接。

序列化机制：RBucket 默认使用 Redisson 配置的 Codec，例如配置 JsonJacksonCodec 后，通过该客户端创建的 Bucket 默认以 JSON 编解码。

五、核心类 Redisson 与 Config

5.1 Redisson 工厂类

Redisson 是框架的核心工厂类，负责创建和管理 RedissonClient 实例，提供静态工厂方法：

  • create()：使用默认配置创建客户端；
  • create(Config config)：按自定义配置创建客户端。

它线程安全，一个应用通常只需要一个 RedissonClient 实例，由工厂统一管理连接池与网络资源。

5.2 Config 配置类

Config 是配置管理类，用于定义 Redis 连接参数与客户端行为：

方法 作用
useSingleServer() 单机连接
useClusterServers() 集群连接
useSentinelServers() 哨兵连接
useMasterSlaveServers() 主从连接
setCodec() 序列化编解码器
setThreads() 业务线程数
setNettyThreads() 网络线程数
setLockWatchdogTimeout() 分布式锁看门狗续期时间

六、分布式锁与看门狗

RLock 是可重入锁：同一线程可以重复加锁。默认开启看门狗机制：持有锁期间后台定期续期，避免业务尚未执行完锁就因超时释放；续期间隔由 lockWatchdogTimeout 控制，默认约 30 秒。业务执行完成后在 finally 中 unlock() 释放锁。

七、小结

  • Redisson 是基于 Redis 的分布式对象与服务框架，在基础客户端之上提供锁、集合、对象缓存等高层抽象；
  • 引入 redisson-spring-boot-starter，通过配置类按单机/集群/哨兵组装 Config 并创建单例 RedissonClient；
  • RedissonClient 是入口工厂，RBucket 封装 String 存取，RLock 提供可重入分布式锁；
  • 可重入锁默认带看门狗自动续期，降低业务未完成锁先过期的风险；Config 统一管理连接、线程、编解码与锁续期参数。
