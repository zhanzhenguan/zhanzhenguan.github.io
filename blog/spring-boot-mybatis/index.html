一、整合 MyBatis

1.1 引入 Maven 依赖

核心依赖：Web 启动器、MySQL 驱动（runtime）、MyBatis Starter；其余按需补充 JDBC、Lombok、测试等依赖：

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>
        <groupId>mysql</groupId>
        <artifactId>mysql-connector-java</artifactId>
        <scope>runtime</scope>
    </dependency>

    <dependency>
        <groupId>org.mybatis.spring.boot</groupId>
        <artifactId>mybatis-spring-boot-starter</artifactId>
        <version>2.3.1</version>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-jdbc</artifactId>
    </dependency>

    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>

1.2 配置 application.yml

在配置文件中配置数据源与 MyBatis：

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: demo
    password: ${DB_PASSWORD:change-me}
    driver-class-name: com.mysql.cj.jdbc.Driver

mybatis:
  mapper-locations: classpath:mapper/*.xml
  type-aliases-package: com.example.po
  configuration:
    map-underscore-to-camel-case: true
    call-setters-on-nulls: false

常用配置项说明：

配置项 作用
mybatis.mapper-locations 指定 mapper.xml 文件路径，SQL 语句写在该文件中
mybatis.type-aliases-package 指定实体类所在包，为实体注册别名；默认使用非限定类名作别名，别名不区分大小写
mybatis.configuration.map-underscore-to-camel-case 开启下划线到驼峰自动映射，如 user_name → userName；默认 false
mybatis.configuration.call-setters-on-nulls 查询结果某字段为 null 时是否调用 setter 给属性赋值；默认 false（不调用）

修正说明：map-underscore-to-camel-case 默认值为 false，默认不会做下划线到驼峰的转换。

1.3 实体类与数据表

实体类 User 封装 id、姓名、年龄、地址、创建时间、修改时间等字段：

@Data
public class User {
    private Long id;
    private String name;
    private Integer age;
    private String address;
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
}

对应 user 表按字段设计建表（示例 DDL）：

CREATE TABLE user (
    id           BIGINT PRIMARY KEY,
    name         VARCHAR(64),
    age          INT,
    address      VARCHAR(255),
    create_time  DATETIME,
    update_time  DATETIME
);

1.4 Mapper 接口与 mapper.xml

UserMapper 接口定义 insertUser（插入）与 findUserById（按 id 查询）：

@Mapper
public interface UserMapper {
    int insertUser(User user);

    User findUserById(Long id);
}

在 resources/mapper/ 下创建 user-mapper.xml：

<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.example.mapper.UserMapper">

    <insert id="insertUser" parameterType="User">
        INSERT INTO user (name, age, address, create_time, update_time)
        VALUES (#{name}, #{age}, #{address}, #{createTime}, #{updateTime})
    </insert>

    <select id="findUserById" resultType="User">
        SELECT id, name, age, address, create_time AS createTime, update_time AS updateTime
        FROM user
        WHERE id = #{id}
    </select>
</mapper>

Mapper 接口与 XML 关联需保证四要素对应：

  1. 接口全限定名 = XML 的 namespace；
  2. 接口方法名 = statement 的 id；
  3. 方法入参 = statement 的入参；
  4. 方法返回值 = statement 的出参。

补充：MyBatis 赋值时不一定调用 setter。若实体有 setId，反射通过 MethodInvoker 调用 setter；没有 setter 时则通过字段 FieldInvoker 直接赋值，细节见 MetaObject 的 setValue 方法。

1.5 Service 与 Mapper 扫描

UserService 注入 UserMapper 并调用增查方法：

@Service
public class UserService {
    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    public void addUser(User user) {
        userMapper.insertUser(user);
    }

    public User findUser(Long id) {
        return userMapper.findUserById(id);
    }
}

为让 Mapper 接口被 Spring 扫描成 Bean，二选一：

  • 启动类加 @MapperScan 指定 Mapper 包（推荐，多 Mapper 时省事）：
@SpringBootApplication
@MapperScan("com.example.mapper")
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
  • 或在每个 Mapper 接口上标注 @Mapper。

1.6 类型别名

配置 type-aliases-package 后，实体默认别名为非限定类名（首字母小写也可，别名不区分大小写，User/user/uSer 等效）。也可在实体上用 @Alias 自定义别名：

@Alias("hello")
@Data
public class User { ... }

注意：@Alias 生效前提是配置了 type-aliases-package；一旦标注，默认别名失效，该实体只能用 hello 作为别名。

1.7 为什么不需要 mybatis-config.xml

Spring Boot 整合 MyBatis 通常不必显式创建 mybatis-config.xml：

  1. 自动配置：MybatisAutoConfiguration 按依赖与约定自动装配组件；
  2. 默认配置：自动配置类内置数据源、事务管理器、SqlSessionFactory、SqlSessionTemplate 等 Bean；
  3. 配置属性：application.yml/properties 中的 MyBatis 属性被自动配置类读取并应用；
  4. Mapper 扫描：自动扫描 @Mapper 或 @MapperScan 指定包下的接口并注册为 Bean；
  5. 集成注解：@Mapper、@MapperScan 完成接口标识与包路径指定。

1.8 自动配置核心类

MybatisAutoConfiguration：MyBatis Spring Boot Starter 提供的自动配置核心类。关键注解：

  • @Configuration：标识配置类；
  • @ConditionalOnClass：classpath 存在 SqlSessionFactory、SqlSessionFactoryBean 时才启用；
  • @ConditionalOnSingleCandidate(DataSource.class)：容器中仅有一个 DataSource Bean 时才启用；
  • @EnableConfigurationProperties：绑定 MybatisProperties；
  • @AutoConfigureAfter：在数据源自动配置之后执行。

核心方法：

  • sqlSessionFactory(DataSource dataSource)：创建 SqlSessionFactory 实例；
  • sqlSessionTemplate(SqlSessionFactory)：线程安全的 SqlSession 实现。

MybatisProperties：MyBatis 配置属性类，集中管理配置项并映射到 Java 对象、提供默认值。主要属性：

属性 含义
configLocation 外部 MyBatis 配置文件路径
mapperLocations Mapper XML 文件路径（数组）
typeAliasesPackage 类型别名包路径
typeAliases 类型别名类数组
typeHandlersPackage 类型处理器包路径
configurationProperties 额外配置属性

二、整合 MyBatis-Plus

2.1 引入依赖

MyBatis-Plus 只需引入 mybatis-plus-boot-starter，其余数据库驱动、Web、Lombok 等依赖与上一节一致：

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-boot-starter</artifactId>
    <version>3.5.5</version>
</dependency>

2.2 常见项目结构

典型分层：po（实体类，可再分 base 放公共基类）、mapper（Mapper 接口）、service（接口）+ impl（实现类）、handler（处理器，如自动填充器）、controller、result（自定义统一返回封装）。

2.3 application.yml 配置

mybatis-plus:
  type-aliases-package: com.example.po
  mapper-locations: classpath:mapper/*.xml
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
    cache-enabled: false
  global-config:
    banner: true
    db-config:
      id-type: ASSIGN_ID
      field-strategy: NOT_NULL
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0

常用配置项说明：

配置项 作用
type-aliases-package 扫描实体包，加载类型别名
configLocation 指定外部 MyBatis 全局配置文件；更推荐直接在 yml 中配置，仅复杂 XML 特性时才用外部文件
mapper-locations 存放 SQL 语句的 XML 目录
configuration.map-underscore-to-camel-case 下划线字段与驼峰属性自动映射；默认 false
configuration.log-impl SQL 日志实现，StdOutImpl 打印 SQL 到控制台
configuration.cache-enabled 是否开启二级缓存；开启后跨 SqlSession 共享查询结果，需注意数据一致性
global-config.banner 是否显示 MyBatis-Plus Banner
global-config.db-config.id-type 主键生成策略（如 ASSIGN_ID 雪花算法、AUTO 数据库自增）
global-config.db-config.field-strategy 插入/更新时字段动态判断策略：NOT_NULL（默认）、NOT_EMPTY、IGNORED
logic-delete-field / logic-delete-value / logic-not-delete-value 逻辑删除字段、已删除值、未删除值
global-config.refresh 运行时刷新 Mapper 缓存，便于开发调试热加载；生产环境不建议开启

修正说明：旧教程提到的 column-underline 已在新版 MyBatis-Plus 废弃，驼峰与下划线映射统一由 configuration.map-underscore-to-camel-case 控制。

2.4 实体类

公共基类 BaseEntity 抽取创建时间、更新时间、逻辑删除标记等公共字段；业务实体 Student 继承基类：

@Data
public class BaseEntity {
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    @TableLogic
    private Integer deleted;
}

@Data
@EqualsAndHashCode(callSuper = true)
@TableName("student")
public class Student extends BaseEntity {
    private Long id;
    private String name;
    private Integer age;
}

2.5 Mapper、Service 与 Controller

Mapper 接口继承 BaseMapper<Student>，即获得单表 CRUD 能力：

public interface StudentMapper extends BaseMapper<Student> {
}

Service 接口继承 IService<Student>；实现类继承 ServiceImpl<StudentMapper, Student>：

public interface StudentService extends IService<Student> {
}

@Service
public class StudentServiceImpl extends ServiceImpl<StudentMapper, Student>
        implements StudentService {
}

Controller 提供新增与查询接口：

@RestController
@RequestMapping("/student")
public class StudentController {
    private final StudentService studentService;

    public StudentController(StudentService studentService) {
        this.studentService = studentService;
    }

    @PostMapping("/add")
    public boolean add(@RequestBody Student student) {
        return studentService.save(student);
    }

    @GetMapping("/query/{id}")
    public Student query(@PathVariable Long id) {
        return studentService.getById(id);
    }
}

主键非自增时，MyBatis-Plus 可按 id-type 策略自动生成长 id；也可采用雪花算法手动 setId。Service 能做的 Mapper 同样能做，Service 内部最终还是走 Mapper，模糊查询等特殊条件可在两者中分别尝试。

三、整合动态数据源

3.1 基本概念

dynamic-datasource-spring-boot-starter 是 MyBatis-Plus 团队提供的基于 Spring Boot 的多数据源管理工具，支持运行时动态切换数据库连接。

核心功能

  • 多数据源支持：配置多个数据库连接，可连接 MySQL、PostgreSQL、Oracle 等不同类型，支持主从、读写分离；
  • 动态切换：通过注解或编程方式切换，支持方法级、类级别切换；
  • 负载均衡：多从库支持轮询、随机等策略。

使用场景：读写分离、多租户、分库分表。

3.2 引入依赖

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>dynamic-datasource-spring-boot-starter</artifactId>
    <version>3.6.1</version>
</dependency>

3.3 配置示例

spring:
  datasource:
    dynamic:
      primary: master
      datasource:
        master:
          url: jdbc:mysql://master-host:3306/demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: demo
          password: ${DB_PASSWORD:change-me}
          driver-class-name: com.mysql.cj.jdbc.Driver
        slave_1:
          url: jdbc:mysql://slave1-host:3306/demo?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
          username: demo
          password: ${DB_PASSWORD:change-me}
          driver-class-name: com.mysql.cj.jdbc.Driver

3.4 @DS 注解切换

在 Service 类或方法上使用 @DS("数据源名") 指定数据源；未标注时使用 primary 指定的主数据源：

@Service
public class OrderService {

    @DS("slave_1")
    public Order queryFromSlave(Long id) {
        // 走 slave_1
        return null;
    }

    public Order save(Order order) {
        // 走默认主库 master
        return order;
    }
}

切换底层基于 ThreadLocal 记录当前数据源标识，再由路由数据源决定使用哪个 DataSource，方法级与类级注解均可生效。

3.5 事务与注意事项

  • 事务边界：在事务中切换数据源需谨慎，建议在事务开始前就确定数据源；跨数据源事务需要单独处理分布式事务；
  • 连接池管理：合理配置各数据源连接池参数；
  • 异常处理：数据源切换失败时的异常要兜底处理；
  • 性能监控：监控各数据源的连接池与 SQL 指标。

组件优点：YAML 配置即可管理多数据源、注解切换便捷、基于 ThreadLocal 开销小、支持负载均衡与健康检查、与 Spring Boot 和 MyBatis-Plus 无缝集成。

四、小结

  • 整合原生 MyBatis：引入 mybatis-spring-boot-starter，yml 配置 mapper-locations 与别名包；Mapper 接口与 XML 通过 namespace、方法 id、入参、出参四要素关联；@MapperScan 批量扫描 Mapper；
  • MyBatis-Plus：Mapper 继承 BaseMapper、Service 继承 IService、实现类继承 ServiceImpl 即可获得单表 CRUD；重点掌握主键策略、字段策略、逻辑删除与驼峰映射配置；
  • 动态数据源：dynamic-datasource-spring-boot-starter 配合 @DS 注解实现方法/类级切换，基于 ThreadLocal 路由；跨库事务要单独设计，生产环境做好监控与异常兜底。
