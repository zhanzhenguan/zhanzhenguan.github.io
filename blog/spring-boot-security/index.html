这篇是 Spring Boot 系列第十三部分，搭建一套基于 Spring Boot 3 + Spring Security 6 + JWT + MyBatis-Plus 的认证授权体系：数据库 RBAC 权限模型、JWT 无状态登录、接口级权限控制。技术栈：Spring Boot 3.5.16、Spring Security 6.x、Java 17、MyBatis-Plus 3.5.12、jjwt 0.12.6、MySQL 8.0。代码为通用示例，连接信息与密钥用占位符。

一、2.x 升级到 3.x 的必改项

老项目从 Spring Boot 2.7 升到 3.x，下面几处必须跟着改，缺一个都跑不起来：

  1. Java 版本：Spring Boot 3.x 强制要求 Java 17 及以上；
  2. MySQL 驱动坐标变了：mysql-connector-java 更名为 mysql-connector-j，groupId 从 mysql 换成 com.mysql，版本由 BOM 统一管理；
  3. MyBatis-Plus 换 Boot3 专用 starter：mybatis-plus-boot-starter 换成 mybatis-plus-spring-boot3-starter，用错 starter 会直接报 MyBatis 版本不兼容；
  4. jjwt 升级到 0.12.x：0.9.x 的 Jwts.parser().setSigningKey(secret) API 已废弃，新写法是 Jwts.parser().verifyWith(key).build()，并需同时引入 jjwt-api、jjwt-impl、jjwt-jackson 三个模块；
  5. Security 6 配置写法重写：WebSecurityConfigurerAdapter 被彻底移除，改为声明 SecurityFilterChain Bean；@EnableGlobalMethodSecurity 换成 @EnableMethodSecurity。

四、RBAC 数据库模型

经典 RBAC 五张表：用户表、角色表、权限表、用户角色关联表、角色权限关联表。

通用 DDL（字段按实际项目调整）：

CREATE TABLE sys_user (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    username    VARCHAR(64) NOT NULL UNIQUE,
    password    VARCHAR(128) NOT NULL,
    nickname    VARCHAR(64),
    deleted     TINYINT NOT NULL DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE sys_role (
    id       BIGINT PRIMARY KEY AUTO_INCREMENT,
    role_key VARCHAR(64) NOT NULL UNIQUE,
    role_name VARCHAR(64) NOT NULL
);

CREATE TABLE sys_permission (
    id             BIGINT PRIMARY KEY AUTO_INCREMENT,
    perm_key       VARCHAR(128) NOT NULL UNIQUE,
    perm_name      VARCHAR(128) NOT NULL
);

CREATE TABLE sys_user_role (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, role_id)
);

CREATE TABLE sys_role_permission (
    role_id       BIGINT NOT NULL,
    permission_id BIGINT NOT NULL,
    PRIMARY KEY (role_id, permission_id)
);

测试账号 admin、user，密码均为 123456：admin 拥有全部权限可访问用户列表和个人信息；user 只有 system:user:info，只能看个人信息。

BCrypt 密文必须对得上明文：不要从网上抄一段密文就用，密文和明文对不上时登录永远报「用户名或密码错误」。正确做法是用 passwordEncoder.encode("123456") 自己生成；换密码也先跑一行代码生成新密文。

五、实体类

用户实体的 password 字段加 @JsonIgnore，用户信息接口不会把密码密文返回前端；不加注解，响应里会带着一长串 BCrypt 密文，属于敏感信息泄露。

@Data
@TableName("sys_user")
public class SysUser {

    private Long id;
    private String username;

    @JsonIgnore
    private String password;

    private String nickname;

    @TableLogic
    private Integer deleted;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    private List<SysRole> roles;
}
@Data
@TableName("sys_role")
public class SysRole {
    private Long id;
    private String roleKey;
    private String roleName;
}
@Data
@TableName("sys_permission")
public class SysPermission {
    private Long id;
    private String permKey;
    private String permName;
}

六、Mapper 接口

用户 Mapper 核心是三个查询：查用户、查角色、查权限。

注意：把「查用户带角色」拆成两条 SQL，而不是一条 JOIN 大宽表。@Select 返回 SysUser 时，JOIN 出来的 role_key 列没有对应映射规则，MyBatis 不会自动拼出 roles 列表；拆成两条单独查询、Service 层组装，逻辑清晰也不会踩映射坑。

@Mapper
public interface SysUserMapper extends BaseMapper<SysUser> {

    @Select("SELECT * FROM sys_user WHERE username = #{username} AND deleted = 0")
    SysUser selectByUsername(String username);

    @Select("SELECT r.* FROM sys_role r " +
            "JOIN sys_user_role ur ON r.id = ur.role_id " +
            "WHERE ur.user_id = #{userId}")
    List<SysRole> selectRolesByUserId(Long userId);

    @Select("SELECT DISTINCT p.perm_key FROM sys_permission p " +
            "JOIN sys_role_permission rp ON p.id = rp.permission_id " +
            "JOIN sys_user_role ur ON rp.role_id = ur.role_id " +
            "WHERE ur.user_id = #{userId}")
    List<String> selectPermsByUserId(Long userId);
}

角色、权限 Mapper 直接继承 BaseMapper 即可。

八、UserDetails 与 UserDetailsService

自定义 UserDetails，把数据库用户包装成 Spring Security 认识的类型。getAuthorities() 把权限标识列表转成 GrantedAuthority 集合，后面 @PreAuthorize("hasAuthority('...')") 校验的就是这里提供的权限。

@Data
public class LoginUser implements UserDetails {

    private final SysUser user;
    private final List<SimpleGrantedAuthority> authorities;

    public LoginUser(SysUser user, List<String> permKeys) {
        this.user = user;
        this.authorities = permKeys.stream()
                .map(SimpleGrantedAuthority::new)
                .toList();
    }

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return authorities;
    }

    @Override
    public String getPassword() {
        return user.getPassword();
    }

    @Override
    public String getUsername() {
        return user.getUsername();
    }

    @Override
    public boolean isAccountNonExpired() { return true; }

    @Override
    public boolean isAccountNonLocked() { return true; }

    @Override
    public boolean isCredentialsNonExpired() { return true; }

    @Override
    public boolean isEnabled() { return true; }
}

认证时从数据库加载用户：

@Service
@RequiredArgsConstructor
public class UserDetailsServiceImpl implements UserDetailsService {

    private final SysUserMapper userMapper;

    @Override
    public UserDetails loadUserByUsername(String username) {
        SysUser user = userMapper.selectByUsername(username);
        if (user == null) {
            throw new UsernameNotFoundException("用户名或密码错误");
        }
        List<String> perms = userMapper.selectPermsByUserId(user.getId());
        return new LoginUser(user, perms);
    }
}

九、JWT 工具类（jjwt 0.12.x 新 API）

0.9.x 老 API 对照：setSubject() 变成 subject()；Jwts.parser().setSigningKey(secret).parseClaimsJws(token).getBody() 变成 Jwts.parser().verifyWith(key).build().parseSignedClaims(token).getPayload()；密钥不再是裸字符串，要用 Keys.hmacShaKeyFor() 构建 SecretKey 对象。

@Slf4j
@Component
public class JwtUtils {

    private final SecretKey key;
    private final long expiration;

    public JwtUtils(@Value("${jwt.secret}") String secret,
                    @Value("${jwt.expiration}") long expiration) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expiration = expiration;
    }

    public String generateToken(String username) {
        Date now = new Date();
        Date expiry = new Date(now.getTime() + expiration);
        return Jwts.builder()
                .subject(username)
                .issuedAt(now)
                .expiration(expiry)
                .signWith(key)
                .compact();
    }

    public String getUsername(String token) {
        return parse(token).getSubject();
    }

    public boolean validate(String token) {
        try {
            parse(token);
            return true;
        } catch (Exception e) {
            log.warn("JWT 校验失败: {}", e.getMessage());
            return false;
        }
    }

    private Claims parse(String token) {
        return Jwts.parser()
                .verifyWith(key)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }
}

十、JWT 认证过滤器

每次请求经过过滤器：从请求头取出 token，验证通过就把认证信息写入 SecurityContext。

注意是 jakarta.servlet 而不是 javax.servlet。Spring Boot 3 基线从 Java EE 升级到 Jakarta EE，所有 servlet 相关包名都有前缀变化，老代码迁移这里是必改项。

@Slf4j
@Component
@RequiredArgsConstructor
public class JwtAuthenticationTokenFilter extends OncePerRequestFilter {

    private final JwtUtils jwtUtils;
    private final UserDetailsServiceImpl userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (jwtUtils.validate(token)
                    && SecurityContextHolder.getContext().getAuthentication() == null) {
                String username = jwtUtils.getUsername(token);
                UserDetails userDetails = userDetailsService.loadUserByUsername(username);
                UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(
                                userDetails, null, userDetails.getAuthorities());
                authentication.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }
        }
        chain.doFilter(request, response);
    }
}

十一、Security 配置类

这是 2.x 升级 3.x 改动最大的文件：

  1. WebSecurityConfigurerAdapter 没了，改用声明式 SecurityFilterChain Bean，配置全部走 Lambda DSL；antMatchers() 改名 requestMatchers()；
  2. AuthenticationManager 不再通过重写方法获得，而是从 AuthenticationConfiguration 中取出；
  3. @EnableGlobalMethodSecurity(prePostEnabled = true) 换成 @EnableMethodSecurity（默认开启 @PreAuthorize 支持）；
  4. CSRF 关闭 + STATELESS 无状态会话，是前后端分离 + JWT 架构的标准配置。
@Configuration
@EnableMethodSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationTokenFilter jwtFilter;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf(csrf -> csrf.disable())
            .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                    .requestMatchers("/auth/login", "/auth/register").permitAll()
                    .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

12.2 认证 Controller

登录走标准认证链：AuthenticationManager.authenticate() 会调用 UserDetailsServiceImpl 从数据库加载用户，再用 BCryptPasswordEncoder 比对密码，任何一环失败都抛异常被捕获返回 401。

@RestController
@RequestMapping("/auth")
@RequiredArgsConstructor
public class AuthController {

    private final AuthenticationManager authenticationManager;
    private final JwtUtils jwtUtils;
    private final SysUserService userService;
    private final PasswordEncoder passwordEncoder;

    @PostMapping("/login")
    public Result<String> login(@RequestBody LoginRequest request) {
        try {
            Authentication authentication = authenticationManager.authenticate(
                    new UsernamePasswordAuthenticationToken(request.username(), request.password()));
            String token = jwtUtils.generateToken(authentication.getName());
            return Result.ok(token);
        } catch (AuthenticationException e) {
            return Result.fail(401, "用户名或密码错误");
        }
    }

    @PostMapping("/register")
    public Result<String> register(@RequestBody RegisterRequest request) {
        if (userService.existsByUsername(request.username())) {
            return Result.fail(400, "用户名已存在");
        }
        SysUser user = new SysUser();
        user.setUsername(request.username());
        user.setPassword(passwordEncoder.encode(request.password()));
        user.setNickname(request.nickname());
        userService.save(user);
        return Result.ok("注册成功");
    }
}

12.3 用户 Controller

/user/list 上的 @PreAuthorize("hasAuthority('system:user:list')") 是方法级权限控制的落点：权限来自登录用户的 getAuthorities()，普通用户 token 访问会被直接拒绝。

@RestController
@RequestMapping("/user")
@RequiredArgsConstructor
public class UserController {

    private final SysUserService userService;

    @GetMapping("/info")
    public Result<LoginUser> info() {
        LoginUser loginUser = (LoginUser) SecurityContextHolder.getContext().getAuthentication().getPrincipal();
        return Result.ok(loginUser);
    }

    @GetMapping("/list")
    @PreAuthorize("hasAuthority('system:user:list')")
    public Result<List<SysUser>> list() {
        return Result.ok(userService.list());
    }
}

十三、测试验证

先执行建库建表脚本，再打包启动。核心链路用 curl 走一遍：

  1. 登录获取 token：POST /auth/login，返回 token；密码输错返回 401；
  2. 获取当前用户信息：GET /user/info，请求头带 token，返回用户与角色权限，密码密文已脱敏；
  3. 获取用户列表（管理员权限）：GET /user/list，admin token 正常返回列表；换成 user token 返回 HTTP 403；不带 token 访问受保护接口同样被拒绝；
  4. 注册与重复注册：POST /auth/register 返回注册成功；重复注册返回「用户名已存在」，新账号可直接登录拿 token。

十四、踩坑与小结

三个实测坑：

  1. BCrypt 密文要对得上明文：密文别从网上抄，用 passwordEncoder.encode("明文") 自己生成；
  2. JWT 密钥至少 32 字节：jjwt 0.12.x 校验长度，短密钥直接抛 WeakKeyException；
  3. 接口别返回密码密文：实体上加 @JsonIgnore，细节虽小，安全意识要有。

小结：

  • 2.x 迁移 3.x 的核心工作量集中在 Java 17、MySQL 驱动换坐标、MP 换 starter、Security 6 配置重写，再加 jjwt 新 API 适配；
  • RBAC 五表分离用户、角色、权限，用户 Mapper 拆条查询由 Service 组装，避免 JOIN 大宽表的映射问题；
  • 认证由 AuthenticationManager + UserDetailsService + BCryptPasswordEncoder 完成，JWT 过滤器把认证信息写入 SecurityContext；
  • 方法级授权用 @PreAuthorize("hasAuthority(...)")，权限标识来自 LoginUser.getAuthorities()；
  • 前后端分离 + JWT 用 STATELESS 会话并关闭 CSRF，密钥与数据库凭据走环境变量注入。
