GitHub Pages 上 _astro 样式 404：被 Jekyll 吃掉的打包资源

2022年6月8日 · 约 3 分钟 · 889 字 #GitHub Pages#Astro#部署#Jekyll#问题排查

把 Astro 站点部署到 GitHub Pages 后，遇到一个很迷惑的问题：页面 HTML 能打开，但样式全丢，浏览器控制台里打包好的 CSS 一直报 404。仓库里点开看，文件明明就在。这篇记录一下排查过程和根因。

一、现象

线上站点 HTML 正常返回，其他静态资源也都能访问，唯独打包到 _astro/ 目录下的样式表访问不到：

资源 状态
首页 / 文章页 HTML 200 正常
/pagefind/pagefind-component-ui.css、.js 200
/favicon.svg、/rss.xml、sitemap 200
/_astro/about.B9tIfBFX.css（打包样式表） 404 缺失

页面能打开，但拿不到 CSS，最终呈现出来就是一堆没有样式的裸文本。

二、排查过程

先排除常见方向：

  1. 不是路径或 base 配置问题：HTML 里 CSS 链接是 /_astro/about.B9tIfBFX.css，站点挂在 Pages 根路径，astro.config.mjs 只配了 site、没有配 base，路径写法本身正确。
  2. 不是本地构建问题：本地 npm run build 通过，dist/_astro/ 里这个 CSS 存在（18KB），文件名和线上 HTML 引用完全一致，本地 preview 样式正常。
  3. 不是文件被 Git 忽略：产物仓根目录没有 .gitignore，也没有规则排除 CSS 或 _astro。
  4. 不是分支不一致：产物仓默认分支是 master，部署脚本也推到 master，master 分支上 index.html 和 CSS 都在；main 分支基本为空。

排查到这里就很反常：HTML、pagefind、favicon、RSS、sitemap 全部 200，唯独 _astro/ 目录下的资源 404。

三、根因：Jekyll 忽略下划线开头的目录

GitHub Pages 默认会经过一套叫 Jekyll 的静态站点处理程序。Jekyll 有一条历史规则：名字以下划线 _ 开头的目录会被直接忽略，不对外提供访问。

  • /favicon.svg、/rss.xml、/pagefind/：目录名没有下划线 → 正常发布；
  • /_astro/：目录名以下划线 _ 开头 → 被 Jekyll 屏蔽，浏览器访问就 404。

这就解释了那个迷惑现象：

GitHub 仓库里文件完整存在 ✅，线上访问 CSS 却 404 ❌

Astro 打包后，所有编译产物默认放在 _astro/ 目录（CSS、JS 都在里面），正好踩中这条规则。

四、解决：放置 .nojekyll 标记文件

.nojekyll 是一个空文件。只要站点根目录存在这个文件，就是告诉 GitHub Pages：

不要运行 Jekyll，不要过滤任何目录，我已经打包好全部静态文件，直接原样对外提供访问。

在 Astro 项目里，把空文件放到 public/.nojekyll：

  • 构建时 public/ 下的文件会原样复制到 dist/ 产物根目录；
  • 部署到 Pages 后，站点根目录就带上了这个文件，Jekyll 过滤被关闭，_astro/ 资源正常放行。

五、故障复盘

完整链路是这样的：

  1. 项目缺少 public/.nojekyll；
  2. 代码推到产物仓，所有文件上传成功，仓库里看一切正常；
  3. GitHub Pages 开启 Jekyll 构建，把 _astro/ 整个目录屏蔽；
  4. 浏览器打开站点，HTML 返回成功，但样式表在被屏蔽的 _astro/ 里 → CSS 404，页面失去样式；
  5. 加上空文件 .nojekyll，提交推送，流水线重新部署；
  6. Pages 检测到该文件，关闭 Jekyll 过滤，_astro/ 资源恢复访问，样式正常。

六、预防建议

  • Astro（或任何纯静态站点）部署到 GitHub Pages 时，记得在 public/ 放一个空的 .nojekyll；
  • 如果线上出现”仓库有文件、页面资源 404”，先区分是路径/base 配错、分支不一致，还是被平台规则过滤；
  • 部署脚本可以在构建后校验关键资源（CSS、JS）是否齐全，避免静默丢资源。

这个坑和代码写错、路径写错无关，纯粹是 GitHub Pages 的 Jekyll 默认规则导致的，新手用 Astro 部署时很容易踩到。
